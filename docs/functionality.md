**What it is.** A local desktop workspace for mathematical and technical documents. Typst, Markdown (print profile) and LaTeX (pdfLaTeX/LuaLaTeX) sources are edited in Monaco and directly on the compiled pages. Both editors share one revisioned document service and one undo history. Python, R and Julia code runs in Jupyter kernels, and the resulting figures and tables can be inserted into documents. Lean files are checked with the project's own toolchain; the verdict comes from a two-step audit that re-checks the file's declarations with the kernel without running the file's code, and the Lean panel lists exactly which declarations were checked. Agent tasks run on the Anthropic Messages API, and the application gates every tool call by scope, consent, permission profile, execution mode and budgets; changes stay reviewable and revertible. Every project has a typed project graph, kept reconciled with its files and open buffers, that the Graph, Research, and Agents pages and agent tasks read and change through one validated service. New projects are created from presets or an objective. Workflow drafts are authored in a form or on a canvas and validated in Rust; a saved, well-formed revision runs only from a run plan the user reviews in full and starts (or, unattended, from a standing plan the user approved for a trigger), one step at a time or up to 4 independent steps at once within application-wide limits, with bounded composites, conditions, and repeats; its Python, R, and Julia steps can run in a local Docker container that sees only their declared inputs, every attempt records its environment, and a run can be exported as a manifest or reproduced from its recorded inputs. Native tools run only in folders the user trusts. Unattended agent execution runs only in a local Docker container.

## 1. Workbench and interactions

### Pages (4)
The window shows one top-level page at a time. The status bar, notifications, command palette and confirmation dialogs are shared by all pages.

| Id | Title · order | Keys | Contents |
|---|---|---|---|

| `research` | Research · 20 | Mod+2 | Research page (§4.1) |
| `agents` | Agents · 30 | Mod+3 | Agents page (§6.13) |
| `graph` | Graph · 40 | Mod+4 | Graph page (§7.2) |

- **Switching:** the rail's "Pages" toolbar (one button per page, `aria-current="page"`, tooltip "<Title> page" + keys; choosing the shown page keeps it shown), or the palette commands "View: Show Editor / Research / Agents / Graph" (`workbench.action.showPage.<id>`, registered per page as pages register). A page shown from a command or key takes keyboard focus (on the Editor page, the editor area); a rail click does not move focus.
- **Mounting:** a page mounts on its first visit, then stays mounted, hidden and inert, while another page is shown; each renders inside its own error boundary. Sidebar-view toggles and the region toggles used from another page show the Editor page first.

Source editor (Monaco): shared document model and shared undo; typing groups until a 1000 ms pause, caret jump, insert/delete switch or line break; banners: changed on disk (Reload from Disk / Keep My Changes), deleted (Keep in Editor), save error (Retry / Dismiss), mixed line endings (read-only; Normalize to LF / CRLF), read-only reason, NUL characters; unavailable states for binary, undecodable and too-large files; aliases (case variants, short names, links) collapse to one canonical tab. Build diagnostics (Typst, LaTeX, Markdown) appear as squiggles with hover text and hints once a build of the shown revision reports; earlier marks stay and move with edits. Lean adds hover, `\` abbreviation completion, go-to-definition and diagnostics. Links in hovers are copied to the clipboard, never opened ("Link copied" / "Link not opened"); URL detection in source text is not bundled.

### 3.2 PDF export (`typesetting_export_pdf`)
- Bytes: Typst/Markdown = `typst_pdf` from the same layout as the pages; LaTeX = the build's own PDF.
- Default destination (the UI always uses it): `<open folder>/<entry folder>/<entry stem>.pdf`. Success → notification "Exported PDF" with path.
- Explicit destination (IPC argument only): absolute, `.pdf` extension (any case), parent folder exists.
- An existing destination must be a regular file starting `%PDF-`, not a file the build read (e.g. an included `.pdf` figure), and not an open document (canonical-path comparison). Otherwise refused: "the destination exists and is not a file" / "refusing to replace a file that is not a PDF" / "refusing to replace a source file of the document".
- Write: temp `<name>.pdf.<pid>.tmp`, then rename; temp removed on failure. The build must belong to the open folder. All export errors surface as `typesetting.export`.

### 3.3 Page edit operations (`page_edit`)
- Ops (only these 4): `insert{text}` (typing, paste, replace-selection), `deleteBackward`, `deleteForward`, `paragraphBreak` (Enter / Shift+Enter). Cut = delete with a selection.
- Outcomes: `applied{revision, caret, mode, rebased}`, `unchanged`, `refused{refusal}`, `stale{currentRevision}` (client maps the selection forward and retries).
- Refusals: `notEditable{reason}` ("not editable on the page (…)"), `wouldChangeStructure` ("…edit in source"), `invalidPosition`, `noChange` (silent).
- `notEditable` reasons — Typst: `code`, `raw`, `comment`, `definition or show rule`, `generated`, `line breaks inside equations`. Markdown: `code`, `raw HTML`, `front matter`, `front matter settings`, `generated content`, `equation delimiters`, `equation structure`, `link or emphasis syntax`, `line breaks inside equations`, `paragraph breaks here`, `table cells`, `footnote definitions`, `setext headings`. LaTeX: `LaTeX markup or generated content`. Any format: `read-only: <reason>`, `the file mixes line endings; normalize them to edit it`, `no page editing for this format yet` (no rules for the extension).
- Transaction: origin `page`, conflict policy rebase-disjoint; consecutive caret typing merges into one undo step (`Typing`), caret deletes merge (`Delete`), Enter = `Paragraph break`; undo/redo shared with the source editor.
- Escaping on insert: Typst escapes markup characters (verified by reparse; three escalation levels); Markdown escapes `\` `` ` `` `$` and context-dependent markers; LaTeX prose: `\` → `\textbackslash{}`, `~` → `\textasciitilde{}`, `^` → `\textasciicircum{}`, `<` `>` `|` → `\textless{}` `\textgreater{}` `\textbar{}`, `"` → ` `` ` (word start) / `''`, `{ } $ & % # _` → backslash-escaped; LaTeX math: `{ } $ & % #` escaped, `\` → `\backslash`, `~` → `\sim`, typed Greek/operators → their macros.
- Refused contexts — Typst: code, raw, comments, `#let`/`#set`/`#show`/closures/loops/imports, generated text. Markdown: code, raw HTML, generated atoms (task boxes, footnote refs, rules), delimiters, `\frac`/`\left` structure, front-matter keys. LaTeX: commands/markup, verbatim (`verbatim`, `lstlisting`, `minted`, `\verb`), comments, `\left`/`\right`/`\big…` delimiters, generated text; Enter only in body prose.

### 3.4 Page images and request limits
- Raster cap: 32 Mi pixels per page image (`MAX_PAGE_IMAGE_PIXELS`); larger LaTeX pages render at a lowered scale. Typst/Markdown SVG is not rasterized.
- `tex_page_image` scale 0.25–8 px/pt; page index < 10 000; build id `tex-…` ≤ 64 chars `[A-Za-z0-9-]`; `page_image` renderRef 1–128 chars `[A-Za-z0-9_-]`; page coordinates must be finite.

### 3.5 Format error codes
- `typesetting.`: `unsupported` (not `.typ`/`.md`/`.markdown`/`.tex`), `noWorkspace` (watch with no folder), `build` (could not run; LaTeX not finished in 600 s or channel closed), `export` (every export failure: invalid/refused destination, unknown build, I/O).
- `tex.`: `unsupportedTarget` (not LaTeX with pdfLaTeX/LuaLaTeX), `workspaceNotOpen`, `noTarget` (no LaTeX target and entry not `.tex`), `unknownBuild` (evicted, unknown, or of a folder no longer open), `noOutput` (no pages), `noSuchPage` (index too high or ≥ 10 000), `invalidScale` (outside 0.25–8 or not finite), `invalidDestination` (defined; unreachable over IPC, export reports `typesetting.export`), `io` (I/O or worker join), `invalidBuildId` (not `tex-…`, > 64 chars, bad characters).
- `page.`: `unknownBuild` (build or page map gone), `invalidRef` (bad renderRef), `unknownPage` (page image gone), `invalidPoint` (non-finite x, y or goalX).
- `page_edit` / `document_*` raw errors (`TransactionError`): `empty`, `unknownDocument`, `duplicateDocument`, `readOnly`, `mixedLineEndings`, `staleRevision`, `conflict`, `historyUnavailable`, `futureRevision`, `invalidRange`, `notCharBoundary`, `overlappingPatches`, `nothingToUndo`.

### 3.6 Files
- Encodings: UTF-8, UTF-8 with BOM, UTF-16 LE/BE with BOM; decoded strictly and saved byte-exactly in the same encoding. UTF-32 BOM or dense control characters (≥ 8 and ≥ 1 %) → `file.binary`; invalid bytes (legacy code pages) → `file.undecodable`; not opened as text.
- Size: open and save limited to 10 MiB (`file.tooLarge`); a save that would produce a file Exposition would refuse to reopen (too large or binary-looking) is refused with the buffer kept.
- Line endings: LF, CRLF, none, or mixed, re-detected on every revision. Mixed (incl. any lone CR) is read-only for every origin (source, page, agent, research, system): only a change whose result is consistent, a reload from disk, or a recovery restore is accepted; undo from mixed into other mixed text is refused. `document_normalize_line_endings` (LF or CRLF) is one undoable "Normalize line endings" step. Source editor and page view show "Mixed line endings" with Normalize to LF / Normalize to CRLF.
- Saves: refused if the file changed on disk since load/save (`file.modifiedOnDisk`) unless overwrite; refused for OS read-only files (`file.readOnly`) and folders; written to `.<name>.exposition-save-<unique>.tmp`, synced, renamed over the original; on failure the temp is removed, original untouched, buffer stays dirty. A deleted file is recreated (missing folders created). Save All reports per-file failures.
- Recovery: dirty buffers journaled (≤ every 300 ms) to the app data folder; journals removed when the buffer is saved, returns to its saved text, or is closed without saving; kept when the folder closes or the app crashes. Next open of the folder lists them (newest first; disk unchanged/changed/missing/unknown); Restore applies them as one undoable "Restore unsaved changes" step (refused if the open buffer has unsaved changes); Discard deletes. Corrupt/newer journals are quarantined (`bad-…`) and shown with their location.
- External changes (watcher, 150 ms settle): clean buffer → reloaded automatically as an undoable `external` step; dirty buffer → conflict banner: modified ("Reload from Disk" = `document_reload`, undoable; "Keep My Changes"), deleted ("Keep in Editor"; buffer marked unsaved, save recreates it), unreadable ("Keep My Changes"); keep = `document_keep_buffer` (next save overwrites); disk matching the buffer again clears the conflict. Failed save → "<name> was not saved" banner with Dismiss / Retry.
- Same physical file reached by another name (link or other spelling) → the same document. Hidden from tree/watcher: `.git`, `.lake`, `node_modules`, `target`, save temps.
- Undo history: 1000 undo steps, 2048 retained revisions per document.

## 5. Lean

- **Project:** folder with `lakefile.lean`/`lakefile.toml`; other files are standalone (root = open folder, pin = nearest `lean-toolchain`). Scan: depth 6, 20,000 entries, skips dot-folders, `.lake`, `lake-packages`, `node_modules`, `target`; runs nothing.
- **Toolchain:** pin = `lean-toolchain`, else elan `default_toolchain` (`ELAN_HOME` or `~/.elan`); channels pick the newest installed match (with a note). Resolved directly to `<ELAN_HOME>/toolchains/<dir>/bin/{lean,lake}`; elan shims never run; nothing downloads implicitly. Version from `lean --version`.
- **Install:** command "Install Project Toolchain" / Infoview banner → confirm (elan downloads from the internet) → needs trust and elan (settings location re-checked at use, `ELAN_HOME/bin`, PATH) → `elan toolchain install <qualified>` trusted batch job (1 h) → waiting files re-attach.
- **Server:** `lake serve` (or `lean --server` for standalone files), one per (project root, toolchain), TrustedNative interactive job; LSP over stdio, Content-Length framed (header ≤ 8 KiB, body ≤ 64 MiB); `hasWidgets:false` (no RPC/widgets). Crash → auto-restart after 1/2/4/8/16 s; Unavailable retried every 10 s and on edit. Stops 120 s after its last file closes, and on folder switch/close or trust revoke; `lean-toolchain`/`lakefile.*` changes restart it. **Restart Lean Server:** shutdown (3 s) + re-attach. **Restart File:** `didClose` + `didOpen` (rebuilds out-of-date imports).

| Feature | Behaviour |
|---|---|
| Diagnostics | the current version only. Messages ≤ 20,000 bytes, with hints for `sorry` and unsolved goals. Monaco markers and Problems (source "Lean") only when they match the editor revision |
| Hover | synced revision only. Untrusted Markdown, no HTML, ≤ 50,000 chars. Links are copied to the clipboard, never opened |
| Goals | cursor or focus, 120 ms debounce → `plainGoal` + `plainTermGoal`. Plain text: hypotheses / `⊢`, "Goal i of n", "Expected type". A newer query cancels the older one |
| Definition | Ctrl+Click, F12 or Go to Definition; ≤ 50 targets. Opens the workspace file, or notifies "Defined outside the workspace" |
| `sorry` marks | semantic tokens `leanSorryLike`, decorated and listed in the Infoview |
| Abbreviations | 202 entries. `\` gives completion (≤ 60). Auto-expands on space, tab, `()[]{},` or newline. Undoable; `\\` does not expand |
| Syntax | Monarch grammar; `sorry`, `admit` and `stop` tokenized as invalid |

| Status (shown as) | Meaning |
|---|---|
| NotStarted (Not checked) | not yet sent to Lean |
| Unavailable (Lean unavailable) | no folder open, or a bad `lean-toolchain` file |
| ToolchainMissing (Toolchain missing) | the pinned toolchain is not installed, or there is no pin and no default |
| Untrusted (Untrusted) | the folder is not trusted; nothing runs |
| Checking (Starting Lean / Checking / Auditing axioms) | the server is starting, Lean is elaborating (progress line), or the audit is running |
| Checked (Checked) | no errors, no `sorry`, reached the end, the kernel re-checked every dependency, only the toolchain's `propext`/`Classical.choice`/`Quot.sound` |
| CheckedWithSorry (Incomplete (sorry)) | depends on `sorry`, including imported or warning-suppressed uses ("found by the axiom audit") |
| ReliesOnCompiledCode (Relies on compiled code) | native evaluation axioms (`native_decide`) or the toolchain's `ofReduceBool`/`ofReduceNat`/`trustCompiler` |
| CheckedWithAxioms (Checked with axioms) | any other axiom. A non-toolchain axiom with a standard name is shown "(declared outside the toolchain)" |
| PartiallyChecked (Partially checked) | stopped before the end (`#exit` or another terminal command) |
| Unverified (Not verified) | the kernel rejected a declaration on replay (for example `skipKernelTC`); a non-toolchain `prelude` module or a declaration named like a constant the kernel evaluates by name; a declaration the language server indexes for this file is missing from the audit (tripwire); or the audit could not run: unsupported toolchain, modified programs, bad output, timeout |
| Errors (N error(s)) | an error diagnostic or a fatal stop; no audit |
| ServerUnavailable (Lean not started) | the server could not start (for example the job limit); retried |
| ServerCrashed (Server crashed) | the server died; shows attempts and whether it is restarting |

The final status is chosen in this order: Errors, Unverified, Partially checked, Incomplete, Relies on compiled code, Checked with axioms, Checked.

**Audit (two steps):**
1. Runs after Lean reports a revision error-free (or speculatively 800 ms after a stable edit, only if its import lines match a version Lean already finished; a failed speculative audit reruns when Lean is done), with the toolchain's `lean`, its library first on `LEAN_PATH` plus the project path from `lake env`, in `%TEMP%\exposition-lean\audit`; nothing written to the project.
2. **Compile** (runs the file's code): elaborates the exact text as a temporary module, writes its `.olean`, reports from frontend snapshots whether elaboration reached the end; only the one line tagged with a per-run secret (sent on stdin, then closed) counts.
3. **Check** (runs none of the file's code): imports only toolchain modules, reads the module and its non-toolchain imports as `.olean` data, refuses non-toolchain `prelude` modules and kernel-special names, replays every non-toolchain dependency into the kernel (`Kernel.Environment.replay`), lists each declaration's axioms with toolchain origin and prints each checked declaration's statement with the toolchain's notation only.
4. **Tripwire:** names written after declaration keywords that the audit lacks are looked up in the language server's `workspace/symbol` index; any hit → Not verified.
5. Both programs are compiled before the first language server for a toolchain starts, SHA-256-pinned, held open with write/delete denied for the service's lifetime (Windows) and re-hashed around each step (tampering → Not verified, recompiled next time); written for Lean 4.35 APIs; 15 min and 32 MiB log per step.

- **`lean_check`** (agents, e2e): target = open document or path (disk text as a temporary document); `checked` only for Checked of that exact revision; diagnostics, `sorry` locations, axioms and goals (≤ 32 positions) only when finished; timeout 120 s default, 600 s max (agent tool: 300 s).
- **Formal evidence (M7):** the service keeps the audit record of each finished revision (`lean_audit_record`: every audited declaration with its statement, axioms, and its own verdict from those axioms (Checked, Checked with axioms, Incomplete, Relies on compiled code) next to the file's status). `lean_record_evidence(document, declarations)` registers service-owned `FormalCheck` evidence per listed declaration (file and declaration verdict, toolchain, sha256 of the audited text, revision, `dependencies: unavailable` "the Lean audit does not report declaration dependencies", no fingerprints, so freshness is never current); names the audit did not list are refused. The declaration is a `FormalDeclaration` entity (key = qualified name, bound to the `.lean` file, `anchoredIn` it). `lean_associate_declaration({declaration: {kind: "audited", document, name} | {kind: "entity", entity}, target, note})` records the reviewed `formalizes` relation (accepted: a correspondence, not a proof of equivalence). `lean_declaration_evidence(document)` lists the evidence history with freshness against the current text (older audits are stale history). The infoview offers Record evidence and Associate with... on checked and audited declarations.
- **Error codes** (23): `lean.` + `invalidDocument`, `invalidRequest`, `stopped`, `closed`, `cancelled`, `timeout`, `serverStopped`, `server`, `unknownDocument`, `noWorkspace`, `stale`, `notReady`, `invalidOffset`, `toolchainInstalled`, `invalidToolchain`, `untrusted`, `noElan`, `notLean`, `unreadable`; formal evidence: `noAudit` (no revision has a finished audit), `notAudited` (the audit did not list that declaration), `notDeclaration` (only a formal declaration can formalize), `associationRefused` (the graph refused the association; its reason). Graph errors during evidence commands keep their `graph.*` code.

### 6.2 Task lifecycle and statuses
- **Create** (`CreateTaskRequest {prompt, workspaceRoot, scope, permission, execution, consent?, budgets?}`): prompt trimmed, 1–100 000 chars; folder absolute, existing, not a drive root, and the open project; budgets in range; files scope non-empty; selection document open at that revision → `queued` → first user message = `<task_context>` (project, scope, document changes, process execution, consent, open in-scope documents with revisions) + `<selection>` only with `scopeContent` + prompt → worker starts.
- **Run loop**: `running` → checkpoint once (hash, revision, unsaved flag of every open document) → per turn: budget check → stream → store assistant content → run each tool call in order → all results in one user message → repeat until end of turn, budget, cancel, error or stop.
- **Continue** (follow-up prompt, optional new budgets; UI sends none): any inactive task; refused while active (`agents.taskRunning`) or while the worker still releases services (`agents.taskFinishing`); folder re-checked; unanswered `tool_use` blocks get their recorded result or "Not executed: the previous run stopped before this tool ran."
- **Cancel**: aborts the stream, an approval wait, or the running tool (tool gets 5 s to report). Worker end: terminal status + notice stored → agent research sessions shut down → `TaskChanged`.

### 6.7 Approvals
- Raised for native launches (Ask mode) and changes in `reviewEdits`: `ApprovalRequest {id "approval-{uuid}", taskId, toolUseId, tool, title, detail}`; memory only; no timeout. - Titles: "Apply edits to {path}" (each replacement −/+), "Create {path}" (bytes + content), "Insert artifact {a} of run {r} into {path}" / "Update attachment {key} in {path} with artifact {a} of run {r}" (placement + exact text + key), "Build {entry} with LaTeX", "Run Python code", "Check {path} with Lean", "Run {program}" (Program / Arguments / Working folder).

### 6.9 Review, accept, revert
- Per file: checkpoint text, baseline (file without this task's changes; concurrent user edits rebased in), tip; `entangled` when a concurrent edit overlapped. States: `pending` (Pending review), `accepted` (Kept), `reverted` (Reverted), `undone` (Undone in editor: derived from current content, never stored; edited change absent or created file missing; redo makes it pending again; an undone revert shows pending).
- Keep / Keep all: refused while active (`agents.taskRunning`); all = effective-pending files only; reverted → "already reverted"; undone → "nothing to keep"; else "Kept."
- Revert / Revert all: refused while active; task folder must be open (`agents.workspaceNotOpen`); edited file: inverse diff as undoable transaction "Revert agent changes" (rebased over later edits, ≤3 retries), refused on overlap or entangled → "Reverted in the open document (not saved)."; created file: deleted only if buffer and disk hold only agent text → "Deleted the file the agent created."
- Diff: read-only Monaco diff, left = without this task's changes, right = after its latest change; side-by-side, inline below 700 px.

### 6.10 Persistence and crash behaviour
- `<data dir>/agents.sqlite3` (WAL, foreign keys, 5 s busy timeout, schema v2; newer schema refused). Tables: `tasks`, `transcript` (full provider history incl. file text read), `tool_calls`, `checkpoints`, `task_files`, `changes` (patches + inverse), `settings`; v2 adds `task_graph` (bound project graph id, kept investigation), `task_graph_contexts` (one per run), `task_targets`, `task_proposals`. No delete or prune: tasks kept indefinitely. Startup: active tasks → `interrupted`; `pending`/`running`/`awaitingApproval` calls → `notRun`; warning notice "Exposition closed while this task was running…". Pending approvals are lost (memory only). Continue resumes.
- Events: `agents:event` (13 kinds: taskChanged, transcriptChanged, streamStarted, textDelta, thinkingDelta, streamReset, toolCallStarted, toolCallFinished, approvalRequested, approvalResolved, fallback, reviewChanged, providerChanged); broadcast capacity 4096; lag → `agents:resync`.

### 6.11 Credentials
- Windows: generic credential target `anthropic-api-key.org.exposition.desktop` (user `anthropic-api-key`), persistence local machine (not roaming). Persistence is never changed in place (Credential Manager would keep the old copy in its other store and bring it back on the next write of that persistence by any program): a roaming copy is deleted before the local one is written, and every save, move, and removal is checked after both stores reload (a throwaway roaming and a throwaway local credential `<target>.settle-roaming` / `.settle-local`, no secret, written and deleted at once), up to 4 attempts. A key saved with roaming persistence by an earlier version is moved to local-machine on first read; one moved in place by an earlier build has its leftover roaming copy removed on first read, keeping the local bytes. macOS Keychain / Linux keyutils via `keyring` (unverified). Debug builds: entry `org.exposition.desktop.development` unless `EXPOSITION_CREDENTIAL_NAMESPACE` (≤64 `[A-Za-z0-9-]`) or `EXPOSITION_USE_REAL_CREDENTIAL=1`; release builds ignore both and use the real entry.
- Key: trimmed, 16–512 ASCII graphic chars (IPC rejects >1 024 bytes); never returned, logged, stored in SQLite or project files; webview clears the field before saving (restored only on failure). ## 7. Project graph, projects, and workflows

Every open project has one typed project graph (`crates/exposition-graph`). It is attached when the folder opens, whether or not a graph view is shown, and a reconciler thread (`graph-reconciler`) keeps it in step with the project's files and open buffers. Rust owns identities, admission, validation, and semantics; the webview reads bounded projections and proposes typed changes (§9 "Project graph"); agents use the same service within their scope (§6.14). Workflow runs (§7.7) are a separate service (`crates/exposition-workflow`) with its own app-local run history; it reads saved workflow revisions from the graph and acts through the research, Lean, graph, and agents services.

- **Attachment markers** (`// exposition:begin|end <key>` in Typst, `% …` in LaTeX, `<!-- … -->` in Markdown): the first image inside a single begin/end pair → `usesAsset` (a generated artifact is admitted, origin `attachment/1`); unpaired or repeated markers yield nothing and are reported.
- **Resolution:** a label resolves to a declaration in the same file, then to a unique live keyed entity; section and equation labels are not entities; a citation resolves to a `reference` by key. A missing or ambiguous target is counted as unresolved and explained, never guessed.
- **References are not dependencies:** extraction produces only `imports`, `usesAsset`, `references`, and `proofOf` (plus `contains` and `anchoredIn` structure). `dependsOn` and `assumes` come only from people, agents (suggested), and presets.
- **File identity:** a rename or move keeps its identity when, within one reconciliation pass, the gone and new paths match one to one by physical file identity, then by identical content; a copy gets a new identity; a file reappearing with identical content at a tombstoned path revives it. Old and new paths seen in different passes are not matched. A folder keeps its identity when all its renamed files agree on one new folder.
- **Declaration identity:** matched by name and kind, then identical text, then identical context, then the same context with one candidate left on each side; only unique matches, never by position. A name declared twice keeps the existing entity with an `ambiguous` binding ("declared n times … none was chosen"), counted, not merged.
- **Tombstones:** a removed declaration, a changed kind, or a deleted file tombstones the entity (bindings `missing`, observed relations removed). A pass never deletes an entity, alters a curated record, or reassigns an identity on an uncertain match. Tombstones are revived only by an exact name or exact text match. Declarations admitted from a Lean audit are never tombstoned (binding `missing` when no longer declared literally).
- **Region bindings** (curated) follow their exact text: found once → resolved at the new range; not found → `missing` ("The bound text was changed or removed."); found several times → `ambiguous`.
- **Unsaved overlay:** 150 ms after an edit, an open buffer with unsaved changes is extracted like a file and kept in memory as an overlay labelled with its revision (`freshness.overlay`). Only queries naming that revision (`graph_inspect_at_source`) see it, marked unsaved; declarations that exist only in the buffer get provisional `ent-unsaved-…` ids that cannot be change targets. Nothing is written to the graph; saving, or undoing back to the saved text, drops it. Buffers over 8 MiB get no overlay.
- **Driver:** file events are coalesced (250 ms quiet, at most 2 s after the first event); a rescan or more than 200 changed paths runs a full pass. Changed paths read as `pending` until a pass that started after the change has processed them. Sync states: `synchronized` (with the last checkpoint time), `reconciling`, `pending{n}`, `unavailable`. `graph_reconcile` ("Reindex project") re-reads every file and rebuilds derived projections without touching curated records.
- **Impact** (`graph_impact`): breadth-first from 1–100 roots, depth 4 by default (≤ 8), ≤ 200 items (≤ 1000), ≤ 20,000 edges examined. Follows incoming `dependsOn`, `assumes`, `proofOf`, `evidenceFor`, `formalizes` (action `needsReview`), `references` (`citationReview`), `usesAsset`, `imports`, `derivedFrom` (`stale`), and `anchoredIn` into a file root (`informational`: declarations in a changed file are listed, their dependents are not); outgoing `proofOf`, `evidenceFor`, `formalizes`; never `contains` or `memberOf`. Rejected relations are skipped; suggested ones are followed and labelled "(suggested relationship)". Reports ≤ 50 cycles, files with unknown coverage (≤ 200), and the evidence of roots and affected items with freshness.

**Storage and recovery**
- `.exposition/graph.sqlite3`, schema 3 (`PRAGMA user_version`; v2 adds the per-file reconciliation checkpoints: coverage `size`, `modified_ms`, `file_identity`, `pending`, and table `source_index`; v3 adds `evidence_seals`). Tables `meta`, `entities`, `bindings`, `relations`, `evidence`, `evidence_seals`, `changes` (newest 10,000 kept), `views`, `workflows`, `coverage`, `source_index`. Writes are refused (`graph.limit`, nothing written) when a commit would exceed any per-table row limit of the validated open (so no write can make the next open refuse the database), and field/record sizes and ≤ 64 bindings per entity are checked on write. Rollback journal (`journal_mode=DELETE`, not WAL), `synchronous=FULL`, 5 s busy timeout. Every statement is parameterized and every read bounded (≤ 20,000 rows).
- **Validated open** (the database is untrusted input): ≤ 1 GiB; SQLite defensive mode with triggers, views, and untrusted schema disabled; a newer `user_version` or vocabulary is refused and left unchanged; `quick_check`; every schema object and every table's column list must be exactly the expected ones (planted triggers, views, or tables are refused); `foreign_key_check`; per-table row limits; every row decoded and bounded (ids, paths without traversal, ranges, short fields ≤ 256, text ≤ 256 KiB, JSON ≤ 1 MiB, relation endpoint rules, at most one project entity). An older graph is backed up (`premigration`) before it is upgraded; the upgrade is refused if the backup fails. A refused database is left byte for byte unchanged.
- **Graph states:** `attached`. `temporaryReadOnly{reason}` when `.exposition` cannot be created, the folder is read-only and has no graph yet, or the database cannot be created (an in-memory graph), or an existing graph is on read-only storage (opened read-only and copied with `VACUUM INTO` to `<data>/graph-temporary/`): indexed and readable, but nothing is written to the project or claimed as saved (the Graph page offers no changes or saved layouts). `unavailable{reason, recovery}` when `.exposition` or the database is a link, not a regular file, or leaves the project, or the schema is newer (Retry), or the database is damaged or refused (Restore one of the ≤ 5 newest backups, Start new, Retry). An unavailable graph is never replaced automatically; source editing keeps working and graph-dependent actions report unavailable.
- **Recovery** (`graph_recover`): only an option the unavailable graph currently offers is performed (backups matched by name), anything else is refused with `graph.recoveryNotOffered`, and nothing is performed through a `.exposition` link or junction. `restoreBackup` copies the backup to `restore-<ms>.sqlite3`, validates and migrates it like any open, then sets the current database aside; `startNew` renames the damaged database and its side files to `graph.damaged-<ms>.sqlite3`. Nothing is deleted.
- **Evidence seals:** evidence a service of this installation registers is sealed with an HMAC-SHA256 (key `<data>/graph-evidence.key`, never in a project) over its id and stored body (table `evidence_seals`). Evidence without a valid seal — for example copied in with a project's `graph.sqlite3` from another computer — is *imported*: shown as a historical claim of its recorded origin (`EntityDetail.importedEvidence`, `MathRow.imported`), with freshness `unknown` ("recorded outside this installation (copied with the project); a historical claim, not verification on this computer"), never `current`.
- **Backups:** `.exposition/graph-backups/graph-<ms>-r<revision>-<reason>.sqlite3` via `VACUUM INTO` (written as `.partial`, then renamed); the newest 8 are kept and leftovers older than 1 h removed. Reasons: `auto` (after the first successful reconciliation of each open, when the newest backup is older than 24 h), `premigration`, `manual` (`graph_backup`). A temporary graph has none (`graph.temporary`).
- **Operation journal** (application data): `<data>/graph-operations/<24 hex of SHA-256 of the lowercased root>/<op>.json`, written via fsync + rename; ≤ 200 records per project (finished ones pruned), ≤ 1 MiB each. Kinds `promotion`, `projectCreation`, `crossService`; states `pending`, `completed`, `failed{message}`, `needsReconciliation{message}`, `resolved{resolution}`. When a project attaches, operations an earlier session left pending become `needsReconciliation`; none is re-run.
- **Saved views:** table `views`; ≤ 5000 positioned nodes, hidden, or collapsed entries; zoom 0.05–8; ≤ 500 listed; replacing needs the view's revision (`graph.staleView`). Saving a view never changes the graph revision or any relation.
- **Events:** `graph:event` (`status{status}`, `changed{delta, origin}` with ≤ 500 ids per delta field then `truncated`, `reconciled{revision, freshness}`; broadcast capacity 1024); `graph:resync` on lag. `EXPOSITION_GRAPH_TRACE` (any value) prints reconciliation timings to stderr.

- **Workflows tab** (`workflows:` "Workflows"): preset cards (New Numerical Experiment Draft, New Formal Audit Draft: saved at once with the active file bound when its type fits (`.py` script, `.typ`/`.tex`/`.md`/`.markdown` manuscript, `.lean` file), then opened), saved drafts (revision, "imported", "can be reviewed and run" / "cannot run yet", an "Agent proposal" badge for drafts an agent task saved, Well-formed / Incomplete draft pill, Open), "Trigger on" (info) / "Trigger suspended" (warning) badges for workflows with an enabled or suspended trigger (read when the list loads, not live), "Recent runs" (all runs of the project, §7.7), Import ("Import a workflow bundle file (a workflow with the workflows it runs), or paste an exposition.workflow/1 or /2 definition …": **Import Bundle…** (native open dialog, `workflow_bundle_import`; the root draft opens, its children are saved but not opened) and the JSON box + Import Draft). Nothing on this tab starts a run.
- **Editor** (`workflow:<id>`): header with revision, imported/preset/unsaved notes, draft-state pill, view switch **Form** / **Canvas** (localStorage `exposition.workflows.view`, default Form), Save Revision (with the draft's revision), **Export revision N…** (the saved revision as a bundle, backend save dialog; unsaved edits are not exported; errors in a "Not exported" banner), and **Review and run…** (opens the plan review, §7.7). Validation in Rust (`workflow_validate(definition, id)`, so a composite that runs the workflow being edited is reported) 200 ms after each change. Using any schema /2 field switches the draft to `exposition.workflow/2`; removing them all returns it to the schema it was saved with. **Form:** General (title, "Most this workflow may run", description, ceiling checkboxes, and "Steps that may run at the same time": "1 — one at a time" (default; no `execution` field) or 2–4, described as "Independent steps and repeat instances run side by side up to this limit and the application's global limits (4 steps in flight, 2 containers, 2 native, 2 model, 1 Lean)."), Inputs (type, project file, version "at run start" (hashed when the plan is made) or pinned SHA-256), Steps from the registered operations (runner title and containment; port bindings offer only compatible, non-downstream sources and, for an input that takes one source, never a for-each step; parameters; prompt; "Write the code here" opens a Monaco editor in the operation's payload language whose code is data of the definition, never a project file), "Runs after (explicit prerequisites; no data)", Outcomes, "Order of steps" (operation, runner, effects). **Composite steps:** New step → "Run a saved workflow" asks for "Workflow to run" (the project's other saved workflows, "Latest revision N", " · incomplete"); the step pins that latest revision and takes its title. Its card: "Runs the saved workflow “<title>” at revision N (pinned) …", ports derived from the child (one required input per child input, one optional output per child outcome), "Show its N step(s) (read-only)" (nested composites expand, up to 3 levels); when the child has a newer revision, an info banner "Revision M of “<title>” is newer" with **Use latest revision (M)**, which changes only the unsaved draft's pin (bindings untouched); "No workflow chosen" / "Revision N could not be loaded" banners. A composite step offers no repeat ("A step that runs a saved workflow runs once; repeat steps inside that workflow instead.") and no condition ("A step that runs a saved workflow cannot carry a condition; put conditions on the steps inside that workflow.", with **Remove the condition** when one is set). **Condition:** "Run this step only when a condition holds" (disabled when no earlier output can be tested), "Tests the output" (outputs of earlier steps that do not run once per value: formal evidence, datasets, or any optional output; choosing one orders that step first), "Negate: run when this does not hold", "Holds when": "Audit verdict is one of…" (checkboxes), "A JSON value compares…" ("JSON pointer (RFC 6901)", empty = the whole document, "The dataset must be JSON of at most 1 MiB."; Comparison =, ≠, <, ≤, >, ≥ for a number, = or ≠ for text and true/false (changing the value type resets it to =); Value type Number / Text / True or false; Value), or "The output was produced"; the summary ends "otherwise it is skipped (condition not met), and steps that need its outputs are skipped too. An unreadable source fails the step." Deleting the source step removes the condition. **Repeat:** "Run once", "Once for each value of a parameter" (operations with parameters: the parameter, then 1–20 values of its kind; the fixed value then reads "Varies: one instance per value"), or "Again until a condition on its output holds" (operations with outputs: the output, negate, a predicate as above, "At most (iterations)" 1–10, default 3, "If it never holds": Fail the step / Use the last iteration's output), with a summary sentence. **Canvas** (React Flow; the keyboard alternative is the Form, and the Inspector below the canvas edits the selected step or input): input, step, and outcome nodes; one typed handle per port (shape and colour by port type, type in text, required inputs marked); data connections solid, prerequisites dashed, annotations dotted, with a legend; dragging an output onto an input adds a data binding only when the form's compatibility rule accepts it (otherwise "Not connected" with the reason, and nothing changes); a step's bottom handle onto another step's top adds a prerequisite; Delete removes the selected connection or step; diagnostics appear as badges on the nodes and ports they name; zoom, Fit to view, Reset view, and "Arrange by dependency order" (clears moved positions); moved positions are kept per workflow in localStorage (`exposition.workflows.layout.<workflow id>`), never in the definition. Below either view: the workflow's runs (§7.7) and its **Triggers** (§7.8). Closing with unsaved changes asks first.
- **Contract** (`exposition.workflow/1`, and `exposition.workflow/2` when a definition uses any of `execution`, `composite`, `condition`, `repeat`; both are read, a `/1` definition using one is refused with `workflow.schema`, and a definition without them serializes exactly as before, keeping its `definitionHash`): inputs (`unset` or a project file at run start or pinned by hash), steps (operation id + version, parameters, optional code (`python`, `r`, or `julia`, as the operation declares) or prompt payload), connections (`data`, `prerequisite`, `annotation`), outcomes (transformedDataset, retainedFigure, retainedTable, investigationReport, auditEvidence, reviewableProposal, manuscriptPromotion), ceiling (execution none / restricted / trustedNative, model requests, retain results, propose changes). Rules: inputs bound, every step's outputs reach an outcome through data connections (a prerequisite orders steps but carries nothing, so a step linked to the result only by one is an orphan; a condition's source counts as used), typed data between steps, effects within the ceiling, outputs validated by the runner, service-owned types produced only by their services; no cycles (a condition's source is ordered before its step). Limits: 50 steps per definition (100 after composites are expanded), 200 connections, 50 inputs, 20 outcomes, 32 parameters per step, code 256 KiB, prompt 32 KiB, title 200, description 4000, definition 1 MiB, ids `[A-Za-z0-9_-]{1,32}`. Parsing is strict for both schemas: an unknown field anywhere, including one beside a tagged value such as `{"kind":"unset","trust":true}`, is refused ("unknown field at /path").
- **Schema /2 fields** (all optional; `deny_unknown_fields`):
  - `execution: {maxParallel}`: 1–4 (`workflow.maxParallel` otherwise); absent = 1.
  - `steps[].composite: {workflow, revision}` with operation `workflow.composite` v1 (`workflow.compositeOperation` unless both are present or both absent). Resolved through the project's saved revisions (`workflow_validate` with the workflow id, `workflow_save`, imports, agents); without a resolver (only blueprint validation) the step is reported `workflow.compositeUnchecked` (warning) and the draft is not runnable. Checks in order: revision 0 or not in the project → `workflow.compositeMissing`; the workflow (any revision) already on the chain of enclosing workflows, the edited one included → `workflow.compositeRecursive`; a fourth level of nesting → `workflow.compositeTooDeep`; more than 300 composite references → `workflow.tooManySteps`; the child validated as a definition of its own (its inputs treated as bound by the parent) → its recursion, depth, and size errors reported as such, any other error as `workflow.compositeNotWellFormed` (with up to 3 messages); its ceiling not within the parent's (execution none < restricted < trusted native, and no model requests, retention, or proposals the parent does not allow) → `workflow.compositeCeiling`. More than 100 steps after expansion → `workflow.tooManySteps`. Derived ports: an input per child external input (same id, label, type; required; one source) and an output per child outcome (optional); containment = the least contained of the child's runners; effects = the union of the child's; limits = their sums. A composite step takes no payload, parameters, condition (`workflow.conditionInvalid`), or repeat (`workflow.repeatInvalid`). Saving a child never changes a parent; "use latest revision" exists only as a parent edit in the editor.
  - `steps[].condition: {source: {step, port}, test, negate}` with `test` one of `{"kind":"verdictIn","verdicts":[…]}` (source port formal evidence; 1–7 distinct labels from exactly Checked, Checked with nonstandard axioms, Incomplete, Relies on compiled code, Partially checked, Unverified, Errors), `{"kind":"jsonCompare","pointer","op","value"}` (source port dataset; pointer empty or `/…`, RFC 6901 escapes, ≤ 256 bytes, no control characters; `op` `eq`/`ne`/`lt`/`le`/`gt`/`ge`; `value` `{"kind":"number","value":"<decimal ≤ 64 chars, exponent ≤ 6 digits>"}` (any `op`; compared exactly as decimals, 1 = 1.0 = 10e-1; the document's integers within 64 bits exactly, its other numbers as the shortest decimal of their double-precision value), `{"kind":"text","value"}` (≤ 1000 chars) or `{"kind":"boolean","value"}` (both `eq`/`ne` only)), or `{"kind":"outputPresent"}` (any port; meaningful for optional outputs). The source must be another step's declared output of a fitting type and not a for-each step (`workflow.conditionSource`); a malformed test is `workflow.conditionInvalid`. The source adds an ordering (and use) edge, so a downstream source is a `workflow.cycle`.
  - `steps[].repeat`: `{"kind":"forEach","parameter","values":[…]}` (a parameter the operation declares and the step does not also set; 1–20 values of its kind; for an operation with a code payload, text values follow the batch rule below) or `{"kind":"until","port","test","negate","maxIterations","onExhausted":"fail"|"useLast"}` (an output of the step itself; a test as above that fits it; 1–10 iterations); an association step (`formal.associateEvidence`, whose proposals are decided once per step) cannot repeat; otherwise `workflow.repeatInvalid`. A for-each step's output may feed only a port that takes several sources and never an outcome directly (`workflow.iterationFanIn`). A for-each step counts as one step against the 100-step expansion limit.
- **Code languages and batch parameters** (M9): an operation with a code payload declares its language (`python`, `r`, `julia`; `workflow.payloadLanguage` "this operation runs a different language" otherwise, rechecked at run time); a code-source input's file must have that language's extension (`.py`; `.R`/`.r`; `.jl`, case-insensitive), checked on direct input connections and, on the expanded definition, through composites (`workflow.inputTypeMismatch`, rule 3: "<path> is not an R script (.R), which Research R batch (restricted) runs" + " (inside composite step “<label>”)"); the plan reports it as `workflow.notWellFormed`, and the batch adapter and research staging refuse it again. Text parameters of an operation with a code payload are passed to the code as one line: no line break, CR, or NUL and ≤ 4096 bytes (`workflow.invalidParameter` "“<label>” is passed to the code as one line, so it cannot contain a line break"; for-each values `workflow.repeatInvalid`); the `value` parameter is at most 1000 bytes. A value that looks like a secret is refused only by the batch runner, before anything runs (`research.invalidRequest`).

- **Runnable** = validation state `wellFormed` AND every step's runner available in the open project now; computed by the workflow run service on every `workflow_validate`, `workflow_save`, `workflow_import`, `workflow_get`, and `workflow_list` (each runner checked once per list). `runnableReason`: "Ready to run: every step's runner is available. Review the run plan to start it.", "The draft has N error(s); fix them before it can run.", or "Not runnable now: step “<label>” (<runner>): <reason>; …". Runner availability: no adapter → `workflow.runnerUnavailable`; a `nativeAccount` runner in an untrusted folder → `workflow.untrustedFolder` ("… runs natively with your account's privileges (not a sandbox); trust the folder first."); `restrictedPython`: the configured image is valid and present locally and the engine reachable (§11), checked without pulling (`workflow.restrictedUnavailable`, "… it never falls back to native execution."); `restrictedR` / `restrictedJulia`: the same for the configured R image / Julia image (`execution.docker.rImage` / `juliaImage`; the Python image is never used; unset → "Restricted execution is unavailable: no R image is configured: choose a local image that provides Rscript as the R image (Settings → Execution). Exposition never pulls images. It never falls back to native execution."); `nativePython`: a trusted folder and a discovered Python interpreter; `nativeR` / `nativeJulia`: a trusted folder and a discovered `Rscript` / `julia` (an available runtime first, else the first with an executable; the kernel is not needed; "No R installation (Rscript) was found for trusted native batches." otherwise); `leanAudit`: available in a trusted folder (the toolchain is resolved when the audit runs); `readOnlyAgent`: the Anthropic provider with a stored key (or, in debug builds, the scripted provider); `researchRetention`, `reviewedPromotion`: the project graph attached for this project; `graphProposal`: always; `composite`: always ("Available: each of its steps is checked with its own runner."), and runnability checks every expanded child step's runner ("composite step “<label>” has no checked steps" / "step “<label>” was not checked" when a child could not be resolved). Batch availability answers are reused for 5 s per (project, language, mode); a batch re-checks its mode itself when it runs.
- **Presets:** Numerical experiment (Python script, or without one an inline code template (standard library only) that reads the optional declared CSV and writes `table.csv` and `figure.svg` into `EXPOSITION_OUTPUT_DIR`; optional data → Python batch run (restricted) → retain figure → optional manuscript promotion; ceiling restricted) and Formal audit (Lean file → audit → associate evidence; ceiling trusted native). An unset file leaves an incomplete draft.
- **Storage:** rows of table `workflows` in `.exposition/graph.sqlite3` (immutable revisions; identical content saves nothing; ≤ 4 MiB per body); each draft is a `Workflow` entity (attributes `workflow.id`, `.revision`, `.hash`, `.state`, `.runnable` (always stored as `false`), `.preset`, `.imported`). Validation state `incomplete` or `wellFormed`; a stored `runnable` is never read (the graph returns `false` with "Runner availability has not been checked for this draft in the open project; it cannot run until it is.", and the IPC commands above replace it). Imports get a fresh id and are marked imported. Schema /2 definitions are stored the same way (the body holds the definition; stored validations list each expanded plan step with its `runnerId` and `compositePath`).
- **Bundles** (`exposition.workflow-bundle/1`, `crates/exposition-graph/src/workflow/interchange.rs`): `{schema, root: {id, revision, definition}, children: [{id, revision, definition}]}`, strict (`deny_unknown_fields`; a key smuggled beside a tagged value is refused too), ≤ 8 MiB, ≤ 32 children, each definition ≤ 1 MiB. **Export** (`workflow_bundle_export`): the root at the given revision (latest when absent) and, recursively, every (workflow, revision) its composites pin, de-duplicated and sorted, pretty JSON; refused with `workflow.exportInvalid` when the root includes itself, nests deeper than 3, names a revision that does not exist ("fix the draft before exporting it"), needs more than 32 children, or exceeds 8 MiB (`workflow.unknown` for an unknown root); definitions only (no trust, approvals, triggers, validation, origin, or run data). Destination: the backend's native save dialog ("Export workflow", filter "Workflow bundle" `.json`, suggested `<title>.workflow.json`; dismissed → `workflow.exportCanceled`, which the UI ignores) or, over IPC, an explicit `path`; either must be an absolute `.json` path whose folder exists and is not inside the project's `.exposition` folder or the app data folder, and not a link or folder (`workflow.file`: "Choose a file by its full location.", "Workflow files are .json files.", "The folder of X does not exist.", "That location holds Exposition's own records; choose another folder.", "X is not a regular file."); an existing file is replaced only when it is a regular file ≤ 8 MiB whose top-level `schema` is `exposition.workflow-bundle/1` (`workflow.invalidDestination`: "Refusing to replace a file that is not an Exposition workflow bundle; choose another name."); written atomically (`workflow.exportFailed`). **Import** (`workflow_bundle_import`, a path from the frontend's open dialog, the same location checks; `workflow.bundleInvalid` for > 8 MiB, non-UTF-8, or any bundle problem): a bundle or a single `/1`/`/2` definition, parsed strictly; every check runs before anything is saved: ≤ 32 children, revisions ≥ 1, each ≤ 1 MiB, no duplicate (id, revision), no child running the root, every pinned reference carried, no recursion or cycle, depth ≤ 3, and no child the root does not run ("a bundle carries only what the root runs"). Then children are saved in dependency order (several revisions of one exported id become successive revisions of one new id), each with its references rewritten to the new ids/revisions, and the root last; every save is an ordinary validated draft with `imported` set (incomplete drafts are saved with their diagnostics). Result `WorkflowBundleImport {root, children[{original, saved, title, state}]}`. Nothing is trusted, approved, triggered, or run. Saves are not one transaction: a storage failure part-way leaves the children already saved as imported drafts. A single definition imports as one draft with its composite references unchanged (they resolve against this project).

### 7.7 Workflow runs (M8, M9)

`crates/exposition-workflow` (`WorkflowRunService`, one per application); commands §9 "Workflow runs"; event `workflow-run` (§10). M9 adds bounded parallel steps, composites (expanded into the plan), conditions, for-each and until repeats, application-wide concurrency limits, budget reservation, and the run cause; triggers are §7.8, environment capture, manifests, and reproduction §7.9. No retries and no open-ended loops.

**Plan** (`workflow_run_plan(id, revision?)`; latest revision when absent). Needs the open project and its attached graph. The saved revision is re-validated (a stored validation is not trusted) and resolved into a `WorkflowRunPlan`:
- `inputs`: every external input as the run will read it: id, label, type, path, SHA-256 and size of the file now (it must resolve inside the project; links leading outside are refused), `pinned` when the definition pins a hash.
- `steps` in dependency order (the order they run, a condition's source before its step): operation and title, runner and title, containment, effects, the complete code or prompt payload, parameters, data bindings, prerequisites, time limit (`timeoutSeconds` clamped to 1 s–the operation's maximum, else the maximum; ≤ 4 h; a for-each step shows the largest of its instances'), output limit (the operation's), `maxModelRequests` (25 for an agent review step, else 0), `available` + `availability`, and (M9) `compositePath`, `condition`, `repeat`. Composite steps are expanded in place into the pinned child's steps with ids `<composite step>/<child step>` (nested `a/b/c`), `compositePath` = the enclosing composite steps' labels, outermost first; the child's inputs are bound to what the parent bound to the composite's ports, the composite's outputs map to the child steps that realize them, a prerequisite on a composite applies to each of its steps, and the child's own `maxParallel`, ceiling, and annotations are not used. An expansion that fails although validation passed blocks the plan (`workflow.compositeNotWellFormed`).
- `budgets` (n = 1 for a step, the number of for-each values, or the until `maxIterations`): `maxSteps` = Σ n; `maxTotalSeconds` = Σ time limit × n, clamped to 1 s–4 h; `maxOutputBytes` = Σ output limit × n, ≤ 1 GiB; `maxModelRequests` = Σ 25 × n over agent review steps. Not editable.
- `maxParallel` (the definition's `execution.maxParallel`, 1–4, default 1) and `limits` (`WorkflowConcurrencyLimits`: `maxActiveRuns` 3, `maxInFlightSteps` 4, `restricted` 2, `native` 2, `agent` 2, `lean` 1; fixed in the application).
- `execution`: restricted backend (`docker`), the configured (Python) image and that image's engine identity `restrictedImageId` (`sha256:…`, from `docker image inspect`; only when a step uses that image), `runnerImages` (M9: `[{runner, image, imageId}]`, one per restricted R/Julia runner the plan uses, each with its own configured image and identity), folder trusted, native steps, model steps. A restricted image whose identity Docker does not report blocks the plan (`workflow.restrictedUnavailable`, "The identity of the restricted image <img> could not be determined …; restricted steps run only in an identified image. Nothing runs natively instead.").
- `inputs[].text`: the complete text of each code input (port types code source and, since M9, Lean source, because elaborating Lean can run code), read from exactly the bytes its SHA-256 names (> 1 MiB → `workflow.codeTooLarge`, not UTF-8 → `workflow.codeNotText`); the plan review shows it on the step that runs it ("Lean source <path> (N lines, <hash>) — the audit elaborates exactly this text (elaboration can run code)").
- `notices`: with `maxParallel` 1 "Nothing runs until you start the run. Steps run one at a time in the order shown; a failed step stops the workflow, and nothing is retried or repeated." (with repeats: "…, and nothing is retried, and repeated steps run only their declared instances."), otherwise "Nothing runs until you start the run. Up to N independent steps run at the same time (a step starts once everything it depends on succeeded; across all runs at most 4 steps at once: 2 restricted, 2 native, 2 agent, 1 Lean). Budgets are reserved before each step starts. A failed step stops the workflow: nothing new starts, steps already running finish, and nothing is retried or repeated." (the same ending with repeats); per condition "“<step>” runs only when <test, negated in plain words when negated, e.g. “the output is not produced”, “the verdict is not one of …”, “the value at /x ≥ 3”> (output “<port>” of “<source>”); otherwise it does not run (condition not met), and the steps that need it are skipped."; per for-each "“<step>” runs once for each of N values of <parameter> (each instance counts as a step)."; per until "“<step>” runs again, at most N times, until <test> for its output “<port>”; if that never happens, the step fails / the last iteration's outputs are used."; restricted steps, one notice per image ("“<step>” runs in the restricted container (docker, image <img>): only the declared inputs and code are staged read-only, with no network and no credentials; outputs are validated before anything uses them."); native steps ("… run natively with your account's privileges. This is not a sandbox."); model steps ("… send the declared material to the model provider."); promotions are only prepared; evidence associations are only proposed and "never assert that a formal declaration is equivalent to an informal statement".
- `blockers` (non-empty: cannot start): `workflow.notWellFormed` (first 3 errors), `workflow.inputMissing`, `workflow.inputChanged` (a pinned hash differs), `workflow.runnerUnavailable` / `workflow.untrustedFolder` / `workflow.restrictedUnavailable` per step, `workflow.compositeNotWellFormed`, `workflow.conditionSource` (a condition reads a for-each step; validation also refuses this), `workflow.activeRun` ("A run of this workflow is active; wait for it to finish or cancel it first." or "3 workflow runs are active (at most 3 at once); wait for one to finish or cancel it first.").
- `approvalHash`: SHA-256 over a canonical serialization (`exposition.workflowRunApproval/2`; `/1` before M9) of the project identity (canonical root, case-insensitive on Windows, with or without `\\?\`), workflow id, revision, definition hash, inputs, every step's approved fields (including payload, parameters, bindings, limits, `maxModelRequests`, `available`, `compositePath`, `condition`, and `repeat`), ceiling, budgets, `maxParallel`, `limits`, and execution (backend, image, and image identity, the runner images; folder trust only when the plan has native steps). Notices, blockers, availability text, times, and the run cause are not covered.
- Plans are kept in memory (≤ 32, shared by manual, reproduction, and trigger plans; the oldest dropped; a trigger's checks use a preview that is not kept and cannot be started, and only the plan of a run it actually starts is kept), expire 30 min after creation, and are single-use: a start request consumes the plan whether or not it starts.
- Plan review additions (M9, `PlanReview.tsx`): under Execution, the R and Julia runner images ("<runner id> runs in `<image>`, exactly the image <hash>", or "(identity not recorded)"); a concurrency row (`plan-concurrency`: "One step at a time." or "Up to N independent steps (or repeat instances) at the same time; a step starts only after everything it reads or runs after has finished.", then "Across all runs: at most 3 active runs (one per workflow) and 4 steps in flight; per kind at once: 2 restricted container, 2 native, 2 model, 1 Lean."); the steps heading "Steps, in the order they run (one at a time)" or "Steps, in dependency order (up to N at a time)"; the expanded steps of each composite grouped under "Inside the workflow step “A” › “B” — N step(s), shown in full", each with its complete code or prompt; per step "Condition" and "Repeats" rows in plain words, and, when steps may run together, limits "reserved from the run's budgets before the step starts, so steps running together cannot exceed them". A reproduction plan adds "Reproduces" ("Run <id>: every input is pinned to the content that run read. The new run records it as its cause.") and a warning banner "The environment changed since the recorded run (N)" listing the drift (recorded and current values) with "Approving runs it in the current environment; the results may differ."

**Start** (`workflow_run_start({plan, approvalHash})`): refused with `workflow.planStale` when the plan is unknown, used, or expired, the hash differs, or another project is open; then the plan is recomputed for the same requested revision and refused with `workflow.planStale` if its hash differs, with what changed ("The plan is out of date: the workflow was saved again (revision a → b); input “x” (path) changed (sha256 … → …); the project folder is no longer trusted; the restricted execution image changed (a → b); the restricted image x is now a different image (sha256:… → sha256:…); the runner of “s” is no longer available; for an R or Julia runner image: the restricted image changed (a → b) / the restricted image x is now a different image (… → …) / the restricted image x is no longer configured / the restricted image x (sha256:…) is now configured (R/Julia runner images); the steps that may run at the same time changed (a → b); the open project changed. Review the new plan before starting."); then the first blocker's code; then `workflow.activeRun` (one active run per workflow, at most 3 application-wide; checked again under the lock). The run (state `running`, every step `pending`, a for-each step's instances created `pending` with their values, the plan exactly as approved, and its `cause`) is written to the store before its runner thread (`workflow-run`) starts and is returned. **Cause** (`WorkflowRunCause`, tagged `kind`): `{manual}` for a reviewed plan the user started, `{trigger, trigger: <id>, changed: [{input, before, after}]}` (bare SHA-256 hex or null) for a trigger's run (§7.8), `{reproduce, of: <run id>}` for a reproduction (§7.9); the cause grants nothing, is not in the approval hash, and reads `manual` for records written before M9. Application code plans with options (`PlanOptions {cause, pins, notices}`: input pins override an input's version and a mismatch blocks with `workflow.inputChanged`; the options are reapplied when the plan is recomputed at start).

**Scheduling.** A step is ready once every step it takes data from, every explicit prerequisite, and its condition's source have finished. Ready steps start in plan order (a for-each step's instances lowest index first), at most `maxParallel` of the run at once (1: exactly one step at a time, in plan order, as in M8), and only while an application-wide slot is free (`limits`, shared by every active run): every step takes one of the 4 in-flight slots plus one of its kind: restricted container (2), native (2), agent review (2), or Lean audit (1, which also takes a native slot); application-service steps (association, retention, promotion) take only the in-flight slot. A step that finds a slot or its budget reservation unavailable waits (it stays `pending`, retried every 20 ms) and is never refused for it; while it waits, later ready steps of the same run do not start either. A step one of whose needs did not run (skipped or condition not met) is `skipped` ("“<step>”, whose output it needs, did not run."; a step that only runs after it: "“<step>”, which it runs after, did not run."); a step one of whose needs failed or was canceled is not started (the run is stopping).

**Conditions** are evaluated once, when the step is ready and the run has a free place. If the source did not run, the step is `skipped` ("“<source>”, whose output its condition reads, did not run.") unless the test is `outputPresent`, which is decided on the missing output. Otherwise the source's validated output is read: a verdict test reads only formal evidence's overall verdict label (exact label or its class: "Errors (3)" is Errors); a JSON comparison re-hashes the dataset file against the digest recorded when it was validated (`workflow.outputChanged` if it differs), reads it only if ≤ 1 MiB, parses it, and resolves the pointer (numbers compared exactly as decimals (a document number with a fraction or beyond the 64-bit integer range is read as its shortest double-precision decimal; "the number cannot be compared" otherwise); text and true/false by equality); `outputPresent` asks whether the optional output was produced; `negate` inverts. False → the step is `conditionNotMet`, never dispatched (no attempt, no usage), with the reason "Its condition did not hold: it runs only when <test, negated in plain words when negated>, and <observation>." (e.g. "the value at /fit/r2 of output “dataset” of “Fit” is 0.42"). A source that cannot be read or does not fit the test (not a dataset file, larger than 1 MiB, not JSON, no value at the pointer, a value of another type, no verdict, an unproduced output for a non-presence test) fails the step with `workflow.conditionUnreadable` as a never-dispatched attempt ("Not started: its condition could not be evaluated: …"), and so the run.

**Repeats.** For-each: each instance runs the step with the parameter set to its value (and its own time limit); adapters also receive the instance index and value. The step succeeds when every instance has; consumers then receive all instances' outputs per bound port in index order. A failed instance fails the step and the run (running instances finish; pending ones are skipped, "The run stopped (a step failed) before this instance could start."). Until: iterations run one after another (an instance is created as each starts); after each, the predicate is evaluated on that iteration's validated output ("Its predicate held: …" / "Its predicate did not hold: …"); when it holds, the step succeeds with that iteration's outputs; after `maxIterations` without it, `fail` fails the step ("Its predicate did not hold in any of its N iterations.", run code `workflow.untilExhausted`) and `useLast` succeeds with the last iteration's outputs. An unreadable predicate fails the iteration, its attempt (code `workflow.conditionUnreadable` or `workflow.outputChanged`, "The iteration ran, but its predicate could not be evaluated (…); its outputs are discarded."), the step, and the run. Every instance counts as one step dispatch, reserves budget, holds a slot, and has its own attempts; output provenance names its `instance`. Batches (every language) receive `EXPOSITION_ITERATION` = the 0-based instance index (repeated steps only) and their own `EXPOSITION_SEED`, and every parameter set on the step after the for-each value is applied as `EXPOSITION_PARAM_<NAME>` (§7.9, Research batches step 4); a for-each over a batch's `value` gives each instance its value as `EXPOSITION_PARAM_VALUE`.

**Before each dispatch**, in order: canceled → run `canceled`; the run's project is no longer the open one → `canceled` with `workflow.projectClosed`; budgets → `workflow.budgetExhausted` ("Not started: the run may dispatch at most N steps." / "… the run's time budget of N s is used up." / "… the run's output budget of N bytes is used up." / "… the run's budget of N model requests is used up."): the step's output limit (when it has one) and, for an agent review, 25 model requests are reserved from what is left after the reservations of the run's steps in flight, and a step whose reservation does not fit while others are in flight waits for them; the grant is min(limit, left) and is released when the step ends; the time budget is wall-clock time since the run started, not reserved; a prerequisite did not succeed → `workflow.prerequisite`; every bound external input re-hashed and equal to the approved hash (`workflow.inputChanged`), every upstream output present (`workflow.missingOutput`) and, for files, re-hashed and equal (`workflow.outputChanged`); a native step's folder still trusted (`workflow.untrustedFolder`); the adapter installed (`workflow.runnerUnavailable`); a restricted step's backend and image equal to the approved ones and the image's current identity equal to the approved identity, for an R or Julia step its runner's bound image and identity (`workflow.restrictedUnavailable`, "Not started: the restricted image is not the image you approved (approved <img> <id>, now …); restricted steps run only in the approved image."); the batch carries the approved identity, the research sandbox refuses another one (`research.imageChanged`), and the container is started from that identity, not the tag; the adapter available now (`workflow.restrictedUnavailable` / `workflow.runnerUnavailable`, "it is never replaced by another runner"). A refusal is recorded as a failed attempt that was never dispatched. Then the attempt is persisted as `intent` (and the step counted) before the service is called; without a durable intent nothing is dispatched. The adapter reports the service operation as soon as it exists (`researchRun`, `leanAudit`, `associationProposal`, `agentTask`, `retain`, `promotion`), and the attempt is persisted as `dispatched` with it. The step's time limit is capped by the run's remaining wall-clock time, and its output limit and model requests by its grant. Every change of the run record is made and written through under one lock, so concurrent steps never lose each other's updates. A panic in a step's service fails the step (`workflow.internal`, "nothing was repeated"); a panic of the runner thread cancels the run's steps and fails the run ("The workflow runner stopped unexpectedly. Nothing was repeated; start a new run."), releasing its slots. A failed or refused step fails the run (the first failure is the run's code): nothing new starts, steps already running finish and keep their results, and the remaining steps become `skipped` ("The run stopped (a step failed) before this step could start."). Model requests a step made count in the run's usage whether it succeeded, failed, was canceled, or had its outputs refused. After a step, usage beyond the output budget fails the run (`workflow.budgetExhausted`); there is no such check for model requests (a review's task is capped at its grant).

**Output validation** (before any consumer or outcome sees an output; the step's own claim is not trusted): formal evidence only from `lean.audit` and retained artifacts only from `artifact.retain` (`workflow.forgedOutput`); the port is a declared output with its declared type, and the value kind matches the type; provenance names this run, step, attempt, instance (repeated steps), and the operation reported at dispatch (a different operation returned at the end is refused); a file must belong to this attempt's research run, lie under `.exposition/artifacts/<research run>/`, resolve inside the project, and match its recorded SHA-256 and size (`workflow.outputChanged` otherwise); a retained artifact must match its digest; formal evidence must carry a SHA-256 that equals the Lean file's current content (`workflow.inputChanged`) and ≤ 2000 declarations; a report ≤ 65,536 characters; a port returned twice is refused. One refused output discards all of the step's outputs and fails it (`workflow.invalidOutput` / `forgedOutput` / `outputChanged`). Every port that a later step binds or a required outcome names must be present (`workflow.missingOutput`, "output port p is realized by the file p.<ext>"). Accepted outputs realize the run's outcomes.

**States.** Run: `running`, `succeeded`, `failed`, `canceled`, `interrupted` (with `code`, `message`, `acknowledged`, `cause`). Step: `pending` (Not reached; also while waiting for a slot), `running`, `succeeded`, `failed`, `canceled`, `skipped` (an earlier step did not produce what it needs, or the run stopped first), `interrupted`, `conditionNotMet` (its own condition did not hold; not a failure). A step has a `reason` when it did not run or ended early, and a repeated step has `instances` (`index`, `parameter` (for-each value, or null for until), `state`, `attempts`, `reason`; its own `attempts` stay empty). A run whose steps were skipped or not met can still succeed; outcomes carry a `reason` when not produced ("“X” succeeded without producing this optional output.", "“X” failed: …", "“X” was canceled.", "“X” was interrupted when Exposition stopped; its result is unknown.", "“X” did not run. <reason>", "“X” ran N instances; each instance's output is listed with the step."). Attempt: `intent` (Dispatch recorded), `dispatched`, `succeeded`, `failed`, `canceled`, `interrupted` (Outcome unknown); each with the operation, intent/dispatch/finish times, code, message, validated outputs, refused outputs (name + reason), and a bounded, redacted log (≤ 65,536 characters, the tail). Usage: steps, seconds, output bytes (accepted files, including files that realize no port), model requests.

**Cancel, project, trust.** `workflow_run_cancel` ("You canceled the run.", `workflow.canceled`) starts nothing new and stops every running step and instance through its service (a batch's job is canceled and its container removed, a review's agent task is canceled, a Lean audit is no longer waited for); the runner waits for all of them, and the command waits up to 5 s for the run to stop (it may return the run still `running`). Running steps and instances become `canceled`; steps never dispatched `skipped` ("The run was canceled before this step could start."); a repeated step between instances `canceled` ("The run stopped before its remaining instances could start."); already validated outputs stay listed. Closing or switching the project cancels every active run of that project (`workflow.projectClosed`, "The project was closed or switched, so the run was canceled. Nothing resumes when the project is reopened."). Revoking trust for the folder (or a folder containing it) cancels every active run there whose plan has a native step (a Lean audit included), all its steps with it (`workflow.untrustedFolder`, "… its native steps run with your account's privileges and need a trusted folder."); the execution service stops its native jobs.

**Restart.** Each change is written through to the store. When the service starts, every run still `running` becomes `interrupted` (`workflow.interrupted`, "Exposition stopped while this run was active. Nothing was resumed or repeated; …"): running steps and instances `interrupted` ("Exposition stopped while this was running; its result is unknown and it was not repeated."), pending steps and instances `skipped` ("Exposition stopped before this could start; nothing resumes."), every attempt in `intent` or `dispatched`, those of instances included, `interrupted` ("… was dispatched when Exposition stopped; its outcome is unknown and it was not repeated." / "… was about to be dispatched …"). Nothing is re-dispatched. `workflow_run_acknowledge` marks an interrupted run reviewed (`acknowledged`; other states `workflow.notInterrupted`); a new run must be planned and started. On app exit the active run's jobs are killed with the execution service. A research batch manifest left `running` reads as failed ("Exposition stopped before this run finished."), and batch staging folders are removed at the next start.

**Adapters.**
- `restrictedPython` / `nativePython`, and (M9) `restrictedR` / `nativeR` / `restrictedJulia` / `nativeJulia` (research batch runner, one adapter per language and mode; the payload must be in the step's language, `workflow.payloadLanguage` "“<label>” runs R code; its code is not R.", and a bound script of another language is refused, `workflow.invalidInput` "Not started: <path> is not an R script (.R), which … runs."): code = the inline payload, or the bound `script` input (exactly one); declared inputs = the files bound to `data`; each output port is offered the extensions its type accepts and the batch exports (dataset: csv, tsv, json, txt; figure: svg, png, jpg, jpeg, pdf; table: csv, tsv, html, json). See **Research batches** below. Batch `succeeded` is required; a non-zero exit, time limit, or flood fails the step with `research.batchFailed` ("The Python batch failed (exit code N): …"); canceled → `workflow.canceled`. Accepted files that realize no port are kept as run artifacts and counted against the output budget. Execution label: restricted container, or trusted native. The batch receives `EXPOSITION_SEED` (§7.9) and reports its environment.
- `leanAudit` (trusted native): exactly one bound Lean file; the operation id (`<path>@<sha256>`) is persisted before Lean runs; the Lean service's check of that file's document (opened if needed; at most 600 s, the operation's limit and the Lean service's maximum) and then its audit record of the same revision and text (`lean.noAudit` otherwise). The audited text's SHA-256 must equal the plan's (`workflow.inputChanged`: an unsaved or changed buffer is not audited on the plan's behalf); no declarations → `lean.noDeclarations`. Output `FormalEvidence {file, fileSha256, verdict, declarations[{name, verdict, statement?, axioms}], evidence: []}`: the file status label (Checked, Checked with nonstandard axioms, Incomplete (n sorry), Relies on compiled code, Partially checked: …, Unverified: …, Errors (n), …; a truncated audit says "audit list truncated: x of y declarations listed; unlisted declarations have no evidence of their own") and each audited declaration's own verdict (Checked, Checked with nonstandard axioms, Incomplete, Relies on compiled code). Records no evidence itself.
- `graphProposal` (`formal.associateEvidence`): exactly one formal-evidence input; the `declarations` parameter (one name per line) must all be in the audit's list (`workflow.declarationNotAudited`; empty = every audited declaration; none → `workflow.nothingAudited`; > 200 → `workflow.tooLarge`); output `AssociationProposal {proposal "assoc-…", declarations, status pending, accepted [], evidence []}`. Records nothing. **Decide** (`workflow_association_decide({run, step, accept[]})`, run not active (`workflow.runActive`), ≤ 200 names): the step's upstream formal evidence is required (`workflow.noProposal`), the proposal must be pending (`workflow.decided`), every accepted name must be in the proposal and the audit (`workflow.declarationNotAudited`); accepted names get service-owned `FormalCheck` evidence through the Lean evidence path, which requires the Lean service's current audit record of the file with the same SHA-256 (`lean.noAudit`, `workflow.inputChanged`); status `accepted` (with `accepted` and `evidence`), or `rejected` when none is accepted. Decide takes the audit step's last successful attempt, of its instances too (an until audit: the iteration whose evidence the association consumed); an association step that itself repeats is refused (`workflow.repeatedProposal`, "This association step ran as several instances; association proposals are decided only for a step that runs once."), although validation and the plan accept it.
- `readOnlyAgent` (`agent.review`): needs the prompt payload and at least one file among the material (files, retained artifacts, and the Lean file of formal evidence; formal-evidence verdicts and earlier reports are added as text, ≤ 32,768 characters); starts an ordinary agent task: scope = those files, permission read-only, execution disabled, consent file contents in scope, budgets `maxTurns` = the step's model-request grant (min(25, what the run has left); a grant of 0 fails the step with `workflow.budgetExhausted`, "The run has no model requests left."), `maxWallMs` = the step's time limit, `maxCommands` 0, others default; the prompt states the step's label, that it is read-only, the material, and the instructions. The task is polled; a task that asks for approval is stopped (`agent.approvalRequested`); budget exceeded → `workflow.budgetExhausted`; refused, failed, stopped → `agent.refused` / `agent.failed` / `agent.stopped`; no answer → `agent.noAnswer`; the step's limit + 30 s → stopped, `workflow.timeout`. Output `Report {text (the last non-empty assistant text, cut after 65,536 characters with "…"), task}`; the task's turns count as the step's model requests. A report is prose, never evidence. Several reviews may run at once (at most 2 across the application), each its own read-only task over its own material; `material` takes several sources, received in connection order (a for-each producer's in index order).
- `researchRetention` (`artifact.retain`): exactly one bound output of a research run (`workflow.notRunOutput` for a plain project file); `ResearchProject::retain` (state active; re-verifies the artifact digest) → `Retained {entity, path, sha256, evidence, researchRun, artifact}` with computational evidence naming the run's actual execution mode.
- `reviewedPromotion` (`manuscript.requestPromotion`): exactly one retained artifact and the `document` parameter; prepares the existing reviewed promotion (§4.1) of that artifact at the end of the manuscript's open document (current revision; optional caption) → `PromotionProposal {promotion, document, status, attachmentKey, expiresAtMs}`. Nothing is inserted until the user approves it in the run view (research promotion commands). When a run is read, a pending proposal reads `accepted` once research follows the attachment in that document or its markers are in the saved file, `rejected` once the user discarded the prepared review, and `expired` when the research service no longer holds it (approved elsewhere without the insertion surviving, or lost when Exposition restarted) or after the 30-min review window.

**Research batches** (`crates/exposition-research/src/sandbox`, `BatchRunner`; restricted = Docker, trusted native = a new process):
1. The project must be research's open workspace (`research.projectNotCurrent`), the request valid (time limit > 0, owner run + step, port names `[A-Za-z0-9_-]{1,64}` not starting with `.`, only exported extensions), and the mode available now, else refused before anything is staged (`research.environmentUnavailable`, "Nothing was run, and nothing runs natively instead."). Restricted: an image configured, a valid reference, Docker found, the engine reachable, the image present locally (`docker image inspect`; never pulled); its image id is recorded, and (M9) the image's environment is read from the per-identity cache or, the first time, probed in its own container before staging (§7.9). Native: a trusted folder and a discovered interpreter of the step's language (Python, `Rscript`, `julia`; the first available one, else the first with an executable); its discovery report is the environment recorded. Restricted R/Julia: their own configured image (never the Python image); no environment probe.
2. **Staging** into `<data>/research/batches/<research run>/work`: only the declared inputs (≤ 32, each ≤ 1 GiB, ≤ 2 GiB in total) and the code (inline ≤ 4 MiB written as `__exposition_main__.py` / `__exposition_main__.R` / `__exposition_main__.jl` by language, a reserved name (a declared input with it is refused); or a declared script of the step's language (`.py`; `.R`/`.r`; `.jl`) at its project path (another extension: `research.invalidRequest` "<path> is not an R script (.R)")), each copied create-new and verified against its SHA-256 while copying (`research.inputChanged`). Every declared path is checked first: no link, junction, or name-surrogate reparse point anywhere on the path, a regular file, not the graph's storage or a path the graph's admission excludes for any reason other than an unrecognised or generated file type (run records, `.exposition/` metadata, version-control and tool folders, agent instruction files: `research.inputRefused`), and the name the file system resolves must be the declared name (no 8.3 or other alias); missing → `research.inputMissing`. A cancel during staging dispatches nothing (`research.batchCanceled`).
3. The manifest (`.exposition/runs/<run>.json`, status running, owner `workflow{run, step}`, the pinned inputs, the code provenance, `execution` = the actual mode) is written before launch; restricted settings that changed since the check refuse the batch. The job is launched through the execution service and the research run id reported.
4. **Batch variables** (M9, every language and mode, checked before anything is staged): `EXPOSITION_SEED=<decimal>`; for a repeated step `EXPOSITION_ITERATION=<0-based instance>`; and each parameter set on the step (for-each value applied) as `EXPOSITION_PARAM_<NAME>`, the name an ASCII identifier ≤ 64 characters converted from camelCase to UPPER_SNAKE (`timeoutSeconds` → `EXPOSITION_PARAM_TIMEOUT_SECONDS`, `value` → `EXPOSITION_PARAM_VALUE`), the value as text (integers in decimal, booleans `true`/`false`); refused before anything runs (`research.invalidRequest`, "parameter `<name>` cannot be given to the batch: …") when the name is not an identifier or looks like a credential, the value is longer than 4096 bytes, is not one line, or contains a secret, or two parameters map to one variable. **Restricted:** a Docker job (flags §11) started from the approved image identity, running `python3 <entry>` (R: `Rscript --vanilla <entry>`; Julia: `julia --startup-file=no --history-file=no <entry>`, in the configured R / Julia image) with the working copy as the registered root, mounted read-only at `/workspace` (the project folder is never mounted), `/out` as the writable output area, and a constructed environment: `PATH`, `HOME=/tmp`, `TMPDIR=/tmp`, `LANG=C.UTF-8`, `EXPOSITION_OUTPUT_DIR=/out`, `PYTHONDONTWRITEBYTECODE=1`, `PYTHONUNBUFFERED=1`, `PYTHONIOENCODING=utf-8`, `MPLBACKEND=Agg`, `MPLCONFIGDIR=/tmp/matplotlib` (Python only; Julia's `PATH` starts with `/usr/local/julia/bin`, its depot is `/tmp/.julia` on the tmpfs, then the image's), and the batch variables. Docker's own failure after the check (exit 125 with a `docker:` line) is reported as the backend unavailable, not as the code's failure. **Trusted native:** the interpreter runs `<work>/<entry>` as a TrustedNative job in the working copy (registered as an application folder bound to the project, so the trust gate applies), with the research environment plus `EXPOSITION_OUTPUT_DIR=<data>/research/batches/<run>/out`, `MPLBACKEND=Agg` (Python only), and the batch variables; R runs the discovered `Rscript --vanilla <script>`, Julia `julia --startup-file=no --history-file=no <script>` (plain absolute paths), with discovery's `R_LIBS_USER` / `JULIA_DEPOT_PATH`; never a user's or an agent's kernel. R and Julia errors are taken from the last `Error in … :` / `Error:` line or the first `ERROR:` (≤ 500 characters).
5. Waiting: cancellation cancels the job (the backend removes the container); the time limit stops it; about every 0.5 s the output area is measured and the job is stopped when it exceeds min(output budget, 512 MiB) + 64 MiB ("wrote more than N MiB to its output area"). Job logs ≤ 1 MiB per stream; the batch log keeps the last 8 KiB of each stream (redacted).
6. **Output registration** (also after a failure): at most 256 entries of the output folder are inspected (more are reported, unread); accepted only regular files directly in it (folders, links, junctions, reparse points, special files, and files with more than one name are refused without being followed), names `[A-Za-z0-9._-]{1,100}` without a leading or trailing dot, not a Windows device name, not `transcript.json`, with an exported extension (png, jpg, jpeg, gif, svg, pdf, csv, tsv, json, txt, html), ≤ 32 files, each ≤ 64 MiB, together ≤ min(output budget, 512 MiB), content matching the type (PNG/JPEG/GIF/PDF magic bytes; SVG: UTF-8 containing `<svg`, no NUL; JSON parses; CSV/TSV/TXT/HTML: UTF-8 without NUL). Text types are redacted, then each file is copied create-new to `.exposition/artifacts/<run>/<name>` with its SHA-256 (figure: png/jpg/jpeg/gif/svg/pdf; table: csv/tsv; data: others). Port `p` is realized by `p.<ext>` (the port's first matching extension); other accepted files are extra artifacts. Every refusal is listed (name + reason) and noted in the run transcript ("Output x was not exported: …").
7. The manifest is finalized (status, exit code, Python exception name and message from stderr, outputs) and the staging folder removed.

**Run monitor** (`workflow-run:<id>` tab "Run: <title>", kept current by `workflow-run` events): state pill; Cancel run (running) or "Review a new run…"; for an interrupted run the banner "The application stopped during this run" ("Nothing was repeated automatically. A step marked “Outcome unknown” may have partly run; check its effects before starting a new run.") with Mark as reviewed and Review a new run; failure banner with the run's code and message; usage bars against the budgets (steps, time, output, model requests); each step with operation, runner, containment badge (Restricted container / Runs natively with your account's privileges / Sends material to the model provider / Application service), state, and its attempts (state, operation, times, error, log, validated outputs with port type and "validated · from <operation> (attempt n)", refused outputs); file outputs show path, media type, size, and SHA-256, images previewed only through `<img>` (SVG included) and CSV/TSV as plain cells (≤ 200 rows), anything else listed only; retained results; formal evidence with the file verdict and each declaration's verdict and axioms; reports as plain text; a promotion proposal ("Review the change…": the prepared markup in full; Discard proposal / Approve insertion or Approve update; while pending, when the prepared change can be reviewed until; once accepted, the inserted attachment key); an association proposal (checklist of the proposed declarations with the audit's verdict, axioms, and statement; Reject all / Accept selected (n); once decided, each declaration marked Associated or Not associated); outcomes (Produced / Not produced, Optional, and the reason when not produced); "The plan exactly as approved" (collapsed). M9 additions: the cause under the header ("Started by you from a reviewed plan."; "Started by trigger <id> under its approved standing plan after N watched input(s) changed." with "<label> (<path>): <old> → <new>" short digests, full in the tooltip, "absent" for none; "Reproduction of run <id>, from a reviewed plan pinned to that run's recorded inputs." with **Open the reproduced run**); while running, **Running now (N)** ("of at most M at once" when M > 1; each step or instance with since-time; "Nothing is in flight: the next step waits for its inputs or a free slot."); a repeated step's sentence and its instances ("<parameter> = <value>" or "Iteration k", state, reason, attempts; "N instances: 2 succeeded, 1 running"), outputs labelled "(attempt n, instance k)"; **Condition not met** ("Not run: its condition was not met. …", info-tinted) distinct from **Skipped** ("Not run: an earlier step did not produce what it needs. …", neutral, dashed); per attempt a collapsed **Environment** (runner and containment, system, image name + identity, interpreter, toolchain + manifest digest, package count + digest with "Show the N package(s)", model, seed, notes; "No environment was recorded for this attempt." for a dispatched attempt without one); after the run, **Export manifest…** (backend save dialog; dismissal quiet; success banner with path, size, SHA-256; errors in a "Not done" banner), a collapsed "Run manifest" section (**Show the manifest**: pretty JSON), and **Reproduce…** (a plan review "Reproduce “<title>”", §7.9). Runs lists: the Workflows tab ("Recent runs", every workflow) and the editor (that workflow): title, revision, start time, "n of m steps" (expanded steps; succeeded and condition-not-met ones count as done), state, "Needs review" for an unacknowledged interrupted run, "Trigger" / "Reproduction" badges, Open.

**Store:** `<data>/workflow-runs.sqlite3` (WAL, `synchronous=FULL`, `trusted_schema=OFF`, 5 s busy timeout), table `runs(id, project, workflow, state, started_at, body)`, keyed by the project identity above, so runs are listed only for their own project; the body is the whole run as JSON (≤ 32 MiB), rewritten on every change. Rows are read as untrusted data: oversized, undecodable, or inconsistent rows (id or state differs from the indexed columns, > 100 steps, > 20 instances per step, > 8 attempts per step or instance, an oversized log) are skipped in lists and refused by id (`workflow.untrusted`). `workflow_runs` returns ≤ 100 runs, newest first; summaries carry the `cause`. A history that cannot be opened is set aside as `workflow-runs.sqlite3.bad-<ms>` (with its `-wal`/`-shm`) and a new one started (in memory if that also fails), so the application always starts. Run ids `wrun-<32 hex>`, plan ids `wplan-<32 hex>`.

### 7.8 Workflow triggers (M9)

`crates/exposition-workflow/src/triggers/` (`TriggerService`, one per application, its own driver thread), `src-tauri/src/workflow_triggers.rs`; commands §9 "Workflow triggers"; event `workflow-trigger` (§10). A trigger is an explicit, user-only standing approval: only the four `workflow_trigger_*` commands (webview only) create or change one; there is no agent tool, and definitions, bundles, blueprints, and the graph have no trigger fields (unknown fields are refused). No record exists until the user enables one.

- **Kinds** (`TriggerKind`, tagged `kind`): `inputsChanged {inputs}`: saved content of these external inputs fires it, and they are the only inputs allowed to change; `interval {minutes, inputs}`: fires every 15–10080 minutes (one week) while the project is open, whether or not anything changed; `inputs` (default none) may change between runs without asking.
- **Standing plan** (`workflow_trigger_plan({workflow, kind})`, latest saved revision; computed as a preview that is not kept as a startable plan): the complete `WorkflowRunPlan` (§7.7, code and Lean texts included), `kind`, `watched` inputs (`{input, label, path, portType}`), `standingHash` = the plan's approval hash computed with each watched input's SHA-256, size, and text blanked (so only the watched content may differ), `mayChange` ("The saved content of “<label>” (<path>, <type>)." per watched input, or "Nothing: every input, step, and setting must stay exactly as reviewed."), `suspendsOn` ("A new revision of “<title>” (this trigger runs revision N only)."; "Any change to the code in “…” (…)." per unwatched code or Lean input, "Any change to “…” (…)." per other unwatched input; "The restricted image <name> becoming a different image (approved: <id>)." per restricted image, R and Julia runner images included; "The project folder's trust: native steps run with your account's privileges and need a trusted folder." when native; always "Trust being revoked for the project folder: every trigger of the folder is suspended." and "Any step's runner becoming unavailable (or available), and any step, budget, or limit changing."), `nativeSteps` (labels), `modelRequestsPerRun` (the plan's `maxModelRequests`), `defaults` (quiet period 10 s, 4 runs/hour, 24 runs/day, native not allowed, model requests min(4 × per run, 1000)), `limits`, `notices`, `blockers` (the plan's, except another run being active), `expiresAtMs` (30 min). Refused: no inputs for `inputsChanged` (`trigger.noInputs`), interval outside 15–10080 (`trigger.invalidInterval`), > 16 inputs (`trigger.tooManyInputs`), an input listed twice (`trigger.duplicateInput`), not a resolved external input of the revision, a missing file included (`trigger.unknownInput`), a code-source or Lean-source input ("“<label>” (<path>) is code[ (Lean elaborates it natively, and `#eval` runs code)]. Code never runs without your review: a change to it suspends the trigger instead of starting a run, so it cannot be watched.", `trigger.codeInputWatched`), a pinned input (`trigger.inputPinned`). Reviews are held in memory (≤ 16).
- **Enable** (`workflow_trigger_enable({plan, standingHash, settings})`): an unknown or used review, or another project → `trigger.planStale`; an expired review or a different hash → `trigger.planStale` (the review is used up); refused settings (`debounceSeconds` 2–3600 for `inputsChanged`, `maxRunsPerHour` 1–12, `maxRunsPerDay` 1–100 and ≥ runs per hour, `maxModelRequestsPerDay` ≤ 1000 → `trigger.invalidSettings`; native steps without `allowNative: true` → `trigger.nativeNotAllowed`; a model-request cap below one run's budget → `trigger.modelCapTooLow`) and an unreadable store (`trigger.storeUnavailable`) leave the review usable for another attempt; no project → `workflow.noProject`; a freshly previewed standing hash that differs → `trigger.planStale` ("The standing plan no longer matches: …"); a non-busy blocker → its code. One trigger per (project, workflow): enabling replaces the existing one's kind, settings, and standing plan, keeping its id and history. ≤ 32 triggers per project (the oldest disabled one is forgotten to make room; else `trigger.tooMany`). The watched inputs' current digests become its baseline. If the store cannot be written (`trigger.storeFailed`, "The triggers could not be saved (…); changes since the last save may not survive a restart."), nothing changes and the review stays usable. Disable (`workflow_trigger_disable`, `trigger.unknown` for an unknown id) drops pending work and is undone if it cannot be saved; resuming is a new review + enable.
- **Listening.** Only for the open project and only after it finished opening and indexing (the graph's first synchronization); then the watched inputs' digests are read again as the new baseline, so nothing fires for the open itself and changes made while the project was closed are never caught up. Input: the workspace watcher's `filesChanged` (any program's change on disk, not only editor saves); a changed path matches an input when equal to it or a folder above it (ASCII case-insensitive on Windows); a lost-track rescan matches everything. A watched change sets the fire time to now + quiet period (restarting it on every change); a change of another plan input (code and Lean sources included, or any input of an interval trigger) schedules a check that can only suspend. Closing or switching the project stops listening and drops pending checks and the queued follow-up; the trigger stays `active`.
- **Firing** (fire time): preview the workflow's plan (not kept, cannot be started; a missing project or graph waits); a standing hash that differs → suspended (`trigger.planChanged`, "The standing plan no longer matches: <what changed>. The trigger is suspended until you review and enable it again."); a non-busy blocker or another planning error → suspended with its code; for an `inputsChanged` trigger, watched content equal to the baseline (the content the last triggered run read, or what was found when listening started) → nothing, and a queued follow-up is dropped (an event with `queued: false`; its "queued" history entry stays); a run of the workflow active, or 3 runs active → `queued` (at most one follow-up; it previews again with whatever is saved then, so the latest change wins; polled after 1 s, then 2, 4, 8, 16, 32, 60, 60 … s while still blocked, and at once when any run ends); over the runs-per-hour, runs-per-day (rolling windows), or model-requests-per-day limit (each fire counts the run's full model-request budget) → deferred until allowed; otherwise a startable plan is made, checked again against the standing plan and the baseline, and started through the run service's normal start check (the full approval hash is recomputed) with cause `trigger` and each changed watched input's before/after SHA-256; the new digests become the baseline. A start refused as stale is retried after the quiet period and suspends the trigger after 3 consecutive refusals; another start error suspends it. After each scheduled fire of an interval trigger (whatever its outcome, unless it was queued or deferred), the next is one interval later; when listening starts (after enabling, reopening, or a restart), the first is one interval later and not before the last fire + one interval.
- **Suspension** (`suspended {code, message}`): `trigger.planChanged` (a new revision, a changed code, Lean, or other unwatched input, an input gone, folder trust for a plan with native steps, a restricted image name naming a different image, a runner becoming unavailable or available, `maxParallel` or any step, budget, or limit), `trigger.trustRevoked` ("Trust was revoked for the project folder, so the trigger is suspended until you review and enable it again.", every active trigger of the revoked folder or below it, with or without native steps), `trigger.nativeNotAllowed` ("The plan has native steps, which this trigger was not allowed to start. The trigger is suspended until you review and enable it again."), and pass-through codes. A suspended trigger does nothing until enabled again. Rate limits and queuing never suspend.
- **Records** (`WorkflowTrigger`): `id` (`wtrg-<32 hex>`), `workflow`, `revision`, `title`, `project` (folder name), `kind`, `watched`, the settings, `modelRequestsPerRun`, `standingHash`, `state` (`active` / `suspended` / `disabled`), `createdAtMs`, `enabledAtMs`, `lastFiredMs`, and the live view `queued`, `nextCheckMs`, `listening`, `runsLastHour`, `runsLastDay`, `modelRequestsLastDay`, `storeProblem` (the store's current read or write problem, on every trigger, else null); `history` (≤ 50, oldest dropped: `enabled {revision}`, `fired {run, changed}`, `queued`, `rateLimited {untilMs}`, `startRefused {code, message}`, `suspended {code, message}`, `disabled`).
- **Store:** `<data>/workflow-triggers.json` (`{"schema":"exposition.workflowTriggers/1","triggers":[…]}`, every project's triggers keyed by the canonical project root, lowercased on Windows; each with its standing plan (payloads included, input text removed), baseline, and fire times); written through a temporary file and a rename. Missing → no triggers. Unparsable or a wrong schema → set aside as `workflow-triggers.json.bad-<ms>` and an empty store started. Unreadable (any other read error, or the set-aside failed) → never overwritten: every change is refused with `trigger.storeUnavailable` ("The trigger store (…) cannot be read (…); triggers cannot be changed until it can be, and it is never overwritten."), and the file is read again on the next enable, disable, or list. A record that cannot be decoded is kept as it is, never fires, and is written back unchanged. Changes the engine makes by itself (a suspension, a fire, a queued follow-up, a new baseline) apply even when they cannot be saved and are reported in `storeProblem`. Never in the project, a definition, or a bundle. On restart active triggers load active and not listening, rate-limit windows persist, nothing catches up.
- **UI** (workflow editor, **Triggers** section below the runs, `TriggersPanel.tsx`): "Off by default. A trigger starts runs by itself only under a standing plan you approve here; agents and imported workflows never enable one."; **New trigger…** (**Replace trigger…** when the workflow has one; disabled, with the reason, like Review and run…) opens the dialog of §1: what to watch (code and Lean inputs left out: "Code and Lean sources cannot be watched (…): changed code always needs a new review.") → the standing plan review with "What may change without asking" and "Anything else suspends it until you review it again" → settings, checked against the limits (runs per hour ≤ runs per day included); every review starts with native steps not allowed → **Enable trigger**, or, when the workflow already has a trigger, a warning "This replaces the current trigger" and **Replace trigger**; a stale review shows "The plan changed since you reviewed it" with **Review the new plan**; an unreadable store "Triggers cannot be saved right now". Card: what it watches or its interval, revision, quiet period, limits, "at most one queued follow-up (the latest change wins)", native permission; last fired, runs this hour/today against the limits, model requests today, next check, enabled time; badges "1 run queued", "Not listening yet" ("It listens once its project is open and has finished indexing."), state Active / Suspended / Off; **Turn off**, **Review and turn on…**; a suspended card shows the backend's reason under "Suspended: the approved plan no longer matches" / "Suspended: folder trust was revoked" / "Suspended: native steps are not allowed" / "Suspended", with **Review again…** (pre-filled, native permission off); a store problem shows "The trigger store could not be saved or read"; "Recent history (N)" (newest 20, with **Open run** for fired runs). The section re-reads on `workflow-trigger` events; the suspension notification is §1.

### 7.9 Environment capture, run manifests, and reproduction (M9)

`crates/exposition-workflow/src/{environment,manifest,reproduce}.rs`, `crates/exposition-research/src/sandbox/image_env.rs`, `crates/exposition-lean/src/provenance.rs`, `src-tauri/src/workflow_repro.rs`; commands §9 "Workflow manifests and reproduction".

- **Environment** (`WorkflowStepAttempt.environment`, recorded when the adapter returns, for attempts that were dispatched; none for attempts refused before dispatch, interrupted by an app stop, or from runs before M9): `runner`, `containment`, `os`, `arch`, `appVersion` (the crates' version, 0.1.0), and as applicable `image {name, id}`, `interpreter {name, version}`, `packages [{name, version}]` (≤ 1000 listed), `packagesDigest` (SHA-256 of the sorted, de-duplicated `name==version\n` lines of every captured package), `toolchain {name, version, manifestDigest}`, `model {provider, model, servedBy?}`, `seed`, `notes` (≤ 16 of ≤ 300 characters; absolute paths replaced by `<path>`). Steps of Exposition's own services record only the base fields; a composite's child steps record their own.
  - *Restricted R/Julia batch*: `image {name, id}` and `interpreter` R / Julia without a version; `os`/`arch` `unknown`; no packages; note "The R image's interpreter version and installed packages are not listed (only Python images are probed); its identity names its exact content." No probe runs.
  - *Restricted Python batch*: `os`/`arch` from inside the image, `interpreter` python + version, every installed distribution (`importlib.metadata`; ≤ 5000 captured, noted when truncated), note "Packages: every installed distribution, listed inside the image by identity (no network, no inputs)." The list comes from `<data>/research/image-environments/<64 hex>.json` (`exposition.imageEnvironment/1`; read only when a regular file ≤ 2 MiB naming the same identity; re-validated; written via a temporary file) or, the first time a batch uses that identity, from a probe: a separate container job ("Restricted image environment probe (…)") started from the identity with the restricted settings (`--network=none`, read-only, non-root, limits; an empty working folder; no host environment) running `python3 -c <probe>`, 30 s limit, output validated as untrusted. A failed probe is noted ("The image's package list could not be captured: …") and retried by the next batch; it never fails the batch.
  - *Native batch*: host `os`/`arch`, the discovered interpreter's name and version, and the packages research discovery checks (Python: jupyter_client, ipykernel, pyzmq, numpy, pandas, matplotlib, scipy, sympy, polars; R: `r` and IRkernel; Julia: `julia`), noted "the research environment report (the packages it checks, not every installed package)". No command runs for this.
  - *Lean audit*: `toolchain` = the audit's resolved toolchain (else the `lean-toolchain` pin) with its version, `manifestDigest` = SHA-256 of `lake-manifest.json` (≤ 4 MiB, inside the project; Lake projects), its pinned dependencies as packages (version = revision), notes (e.g. "mathlib revision …"). Files only.
  - *Agent review*: `model` = the provider and the configured model, `servedBy` = the model the provider reported serving (when it did), notes "Configured model …; the provider served …." when they differ, "Effort …".
  - *Seed*: `EXPOSITION_SEED` = the first 8 hex digits of SHA-256(`exposition.workflowSeed/1\n<basis>\n<step>\n<instance>`) as a decimal number (0–4294967295), basis = the run id (for a reproduction, the original's, following up to 32 reproductions), instance = the 0-based instance index (0 for a step that runs once), so instances get different seeds; given to every restricted and native batch (Python, R, Julia) and recorded (also in the research run record).
- **Manifest** (`workflow_run_manifest(run)` → string; `exposition.workflowRunManifest/2`): `schema`, `generator` ("Exposition <version>"), `run`, `cause`, `workflow`, `title`, `project` (folder name), `revision`, `definitionHash`, `approvalHash`, `state`, `code`, `message`, start/finish times, `inputs` (id, label, type, project-relative path, SHA-256, bytes, pinned), `execution` (restricted backend, image, image id, `runnerImages`, native and model steps), `budgets`, `usage`, `steps` (step, label, operation, runner, containment, state, `payloadSha256` (SHA-256 of the exact UTF-8 code or prompt text; null without a payload), parameters, time limit, attempts with times, code, message, environment, outputs, refused outputs, and for a repeated step `instances [{index (0-based), parameter, state, reason, attempts}]`), `outputs` (each step's, and each instance's, last succeeded attempt: port, type, kind, path, SHA-256, bytes, media type, status, provenance, `instance` (null for a step that runs once)), `outcomes` (realized, SHA-256). Left out: logs, report text (digest only), payload text, notices, blockers. Canonical: keys sorted at every level, 2-space indentation, LF, final newline. Scrubbed (every string value): the project root → `<project>`, the app data folder → `<app data>`, the home folder → `~`, other absolute paths → `<path>`, then the execution service's secret redaction.
- **Export** (`workflow_run_manifest_export(run, destination?)`): without `destination` the backend's native save dialog ("Export run manifest", JSON, suggested `<title>-run-manifest.json`; dismissed → `workflow.exportCanceled`, which the UI ignores); with one (IPC callers such as e2e), that path. Either goes through the bundle export's location rules (§7.5, `workflow.file`: absolute, `.json`, an existing folder outside the project's `.exposition` folder and the app data folder, not a link or folder); an existing file must be a regular file of at most 16 MiB whose JSON `schema` is `exposition.workflowRunManifest/1` or `/2` (an earlier export) (`workflow.invalidDestination`: "The existing destination is too large to be a run manifest; refusing to replace it." / "Refusing to replace a file that is not an Exposition run manifest."); a manifest > 16 MiB → `workflow.tooLarge`; atomic write (`workflow.exportFailed`). Returns `{path (as chosen), sha256, bytes}`.
- **Reproduce** (`workflow_run_reproduce_plan(run)` → `WorkflowReproducePlan {plan, reproduces, drift}`): a run of the open project (`workflow.unknownRun`) that is not running (`workflow.runActive`; interrupted, failed, and canceled runs can be reproduced); its revision must still exist (`workflow.unknown`) with the same definition hash (`workflow.reproduceRevisionChanged`). The plan is the normal plan of that revision with cause `reproduce` and every input pinned to the SHA-256 the run read; a differing file blocks it (`workflow.inputChanged`, "<path> changed since run <id> read it (recorded sha256 …, now …); restore that version to reproduce the run."), a missing one `workflow.inputMissing`. `drift` (per step: `aspect` `image` / `platform` / `interpreter` / `toolchain` / `lakeManifest` / `packages` / `model` / `appVersion` / `unrecorded` / `unknown`, recorded, current, message) compares the recorded environment with what is known now without running anything: the configured image's identity (`docker image inspect`) and its cached package list, native discovery's cached report, the agents' provider settings (the configured model is compared, not the served one), the Lean project's files. A repeated step's instances are compared one by one: an item that holds for every instance is reported once, one that holds for some names them ("(instances 1, 3)", numbered from 1); a step or instance that ran without recording an environment gives `unrecorded` saying why ("no environment was recorded [for instance 2] (the application stopped while it ran (interrupted) / it was never dispatched / the run predates environment capture)"). Notices: "This plan reproduces run <id> (revision N): every input is pinned to the SHA-256 that run read, and a changed input blocks the plan. Environment differences are shown so you can judge them; they do not block the run.", one "Environment drift in “<step>”: …." per step or "No environment drift found in what can be checked without running anything (image identity, interpreter and toolchain versions, package lists, model).", and "Batch steps receive the same EXPOSITION_SEED values as in the original run (…)." (instances as "“<step>” #k <seed>"). Started with the normal `workflow_run_start`; the new run's cause is `{reproduce, of}`.

## 13. Security boundaries

- **CSP:** `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; font-src 'self' data:; worker-src 'self' blob:; connect-src ipc: http://ipc.localhost; object-src 'none'; frame-src 'none'; base-uri 'none'; form-action 'none'`.
- **ACL:** one capability `main-window` (window `main`): `core:event:default`, `core:window:allow-set-title`, `core:window:allow-destroy`, `dialog:allow-open` + 161 `allow-<command>`; no `core:default`, no `dialog:allow-save` (export save dialogs are opened by the backend), no fs/shell/http/opener plugin; debug builds add `dev-execution-probe`, `dev-agents-scripted`, and `dev-research-faults` at runtime.
- **Check-permissions gate:** `npm run check` fails when any `src-tauri/permissions/autogenerated/*.toml` matches no `COMMANDS`/`DEV_COMMANDS` entry (now 165 files = 161 + 4); the same pipeline runs the private-path guard and bindings drift check.
- **IPC boundary:** no command runs an arbitrary program; ids, sizes, page indexes, coordinates validated; `WorkspacePath` rejects absolute, `..`, reserved names and invalid characters during deserialization.
- **Trust model:** trust lives in `<data>/execution/trust.json`, never in the project; opening never runs code or grants trust; native jobs (TeX, kernels, Lean, commands) need a trusted folder, re-checked at spawn; revoke cancels the folder's jobs (≤10 s each) and broadcasts `trust:changed` to every view.
- **Too-broad folders:** drive/share roots, personal folders and their ancestors, system folders and anything inside them cannot be opened or trusted; compared by canonical text and by file identity (volume serial + file index), so `\\localhost\C$\…`, `\\127.0.0.1\C$\…`, `\\?\UNC\localhost\C$\…`, `\\localhost\ADMIN$` aliases are refused.
- **Data folder:** never a project (is, inside, or contains `<data>` → `workspace.tooBroad`) and never trustable (nor anything above or inside it), by name and identity.
- **Tool-location re-check:** a configured tool path inside an open project or the execution data folder (name or identity) is refused when set and at every use (jobs, probes, TeX, Docker, sweep) → `RefusedOverride` / `programRefused`.
- **Program validation:** absolute path or catalog id; Windows runs `.exe` only (`.bat`, `.cmd`, `cmd.exe` refused); no `..`; argument arrays, no shell; NUL refused.
- **Environment scrubbing:** child env built from empty (28-name base list, constructed `PATH`, job allowlist); credential-like names or secret-looking values make the job fail (`environmentRefused`), never silently filtered.
- **Restricted backend:** Docker only; explicit, locally present image checked by one reference grammar in settings and at launch; flags in §11; settings refuse root `uid:gid`, invalid memory/cpus/pids; never a native fallback. Workflow restricted batches use the same backend (R and Julia only with their own configured images, each bound by identity in the plan, re-checked at dispatch, and started by identity) with a staged working copy of only their declared inputs and code as the read-only mount (never the project), refuse a batch whose Docker settings changed after the check, and record the image, image id, user, and limits in the run manifest (§7.7).
- **Container lifetime:** batch jobs hold stdin as a liveness pipe, so the container kills itself when the app exits or crashes; in-container `sleep <limit+5 s> && kill -9`; `--rm`; cancel/timeout `docker rm -f`; leftovers of this data folder swept at startup and before the first restricted job.
- **Redaction:** job output, events and summaries redact literal values of credential-named host variables (≥8 chars) and token shapes (`sk-ant-`, `sk-`, `gh[pousr]_`, `github_pat_`, `glpat-`, `npm_`, `hf_`, `xox?-`, `AKIA|ASIA`, `AIza`, `bearer`, PEM keys) to `[REDACTED]`; kernel stream/display/error output redacted; text artifacts (HTML, SVG, CSV, JSON) redacted and rewritten before registration; provider errors replace the key with `<redacted>`.
- **Credentials:** the key lives only in the OS store, kept machine-local on Windows; the webview learns only "configured"; it never enters child envs, the database or logs; validation errors never echo it; debug builds use a `development` entry unless told otherwise; output redaction matches it by its value (registered when read or saved) and by token shape; it is sent only to the fixed endpoint, redirects never followed; code trusted to run as the user can still read it.
- **Project path rules:** reads and writes canonicalize and must stay inside the root (`path.outsideWorkspace`, `path.brokenLink`); aliases (case, 8.3, links, hard links) map to one document; link-following listing stays inside the root; resolve-then-act is not atomic (TOCTOU).
- **Saves:** temp file + fsync + rename, original untouched on failure; refused if the disk hash changed (unless Overwrite), read-only, a folder, too large, or binary; rename breaks hard links, so a file outside the folder is never written.
- **Rendering:** Typst pages as SVG `<img>`; kernel HTML parsed inert with handlers neutralized; Lean hovers untrusted (no HTML, no command links), goals plain text; editor links copied, never opened.
- **TeX:** builds require trust; `-no-shell-escape`, `shell_escape=f`, `openout_any=p`; reads are not confined, hence the trust requirement; the engine writes only to the app-owned mirror/out dirs; rendered pages capped at 32 Mi pixels.
- **Builds and exports:** builds of a folder no longer open are never served or exported; export refuses an existing destination that is not a file or not a PDF, a source, an open document, or a build input.
- **Research:** sessions need trust and are bound to one root; only discovered environment ids launch; project venvs probed only when trusted (`-I`); the folder reaches R/Julia as bytes, never spliced into code; webview sessions are owner `User`; interrupt/restart/shutdown/cancel have no owner check (the user may stop agent sessions).
- **Lean:** server, audit and install run TrustedNative; elan shims never run; no implicit downloads; audit step 2 runs none of the file's code; audit programs SHA-256-pinned and held open deny-write; outputs tagged with per-run secret/nonce; name tripwire against the server's index.
- **Agents:** one central gate checks each tool call's declared reads/changes/runs against scope, consent, profile, execution mode and budgets before anything happens (§6).
- **Project graph:** the project's `graph.sqlite3` is untrusted input: opened only if ≤ 1 GiB, a regular file inside a real `.exposition` folder (no links), with SQLite defensive mode and triggers, views, and untrusted schema disabled, exactly the expected schema objects and columns, `quick_check`, foreign keys, and every row decoded and bounded; a refused database is left unchanged and never replaced automatically (§7.1). Statements are parameterized and reads bounded. No SQL, no service-owned records (evidence, observed relations, service batches: `graph.notService`), and no execution are reachable over IPC; the webview's changes are attributed to the user and agents' to their task by the backend, never by the payload; agents' relations stay suggestions; validated proposals can be applied only by the origin that made them. Ids from IPC or the database are validated and never interpreted. The graph's own storage is never an agent file-tool target (`agents.graphStorage`). Saved views are presentation only.
- **Project creation:** blueprints (presets, agent proposals, imports) are parsed strictly in Rust before anything is written; no trust, run, startup-hook, or grant fields exist; paths are relative and confined, with tool folders, startup-hook files, executable extensions, and `.exposition/` content (except the research space) refused; files are created with create-new semantics (never replaced) in a new or empty folder that the workspace would open; a trusted parent folder needs explicit acknowledgement. Creation grants no trust, runs no code, installs nothing, and sends nothing to a model; only built-in presets assert relations.
- **Workflow drafts:** imported definitions and bundles are untrusted data (strict schema, unknown fields refused anywhere, ≤ 1 MiB per definition, ≤ 8 MiB per bundle, fresh ids, every structural check before anything is saved); saving, importing, or an agent's `workflow_propose` never runs anything; a stored or imported `runnable` claim is never read: runnability is recomputed for the open project from validation and runner availability. A composite's child is validated and expanded from the project's own saved revisions, its ceiling must fit within the parent's, and its pin never moves without a parent edit. Agents can propose only schema `/1` definitions and cannot revise a workflow that uses schema /2 features (`agents.workflowUnsupported`). Script inputs must be in the step's language, also through composites; batch parameters reach code only as validated one-line environment variables.
- **Exports:** a bundle or run manifest is written by the backend to a `.json` file the user picked in the backend's save dialog (or a path an IPC caller gives); an existing file is replaced only when it is an earlier bundle or manifest (by its `schema`); both exports and the bundle import refuse locations in the project's `.exposition` folder and the app data folder, links, and folders; manifests are scrubbed of local paths and secrets and carry no logs, code, or report text; bundles carry definitions only.
- **Workflow triggers:** only the user's webview commands create or change a trigger (no agent tool; definitions, bundles, blueprints, and the graph cannot carry one); enabling requires the hash of a standing plan reviewed in the last 30 min and recomputed identical; a trigger's run starts through the normal start check, and any change beyond the watched inputs' content suspends it; checks preview the plan without keeping it; code and Lean inputs cannot be watched, and their full text is in every plan; native steps need explicit per-trigger permission; rate and model-request limits are enforced by the engine; nothing fires on project open or catches up on changes made while closed; revoking trust suspends the folder's triggers; records live only in the app data folder, and an unreadable store is never overwritten; every review starts with native permission off.
- **Workflow runs:** a run starts only through `workflow_run_start` with the id and approval hash of a plan made in the last 30 min (or from a trigger's standing plan, §7.8), after the plan is recomputed and found identical (inputs by SHA-256, payloads, runners, budgets, conditions, repeats, composite expansion, `maxParallel` and the concurrency limits, image and its identity, folder trust when native steps exist, project); one run per workflow and at most 3 at once, with application-wide step slots; budgets reserved before each dispatch; steps are re-checked before each dispatch (project, cancellation, budgets, input and upstream digests, trust for native steps, the approved restricted image identity, runner availability; a restricted step is never downgraded and its container starts from the approved identity); outputs are validated in Rust (declared port and type, recomputed SHA-256, provenance against the dispatched operation, service-owned types only from their owning operation) before any consumer; interrupted runs are never resumed or replayed; agent review steps are read-only, run no processes, approve nothing, and count against the run's model-request budget; promotions and evidence associations are only proposed until the user approves them. Run records are app-local and read back as untrusted data.

## 15. Known limitations

From `docs/capabilities.md` (verified where code allows) plus code findings (marked *code*).
- Windows 11 x64 is the only verified platform; macOS/Linux build but are unverified (Unix process-group containment unverified).
- The NSIS installer (per user, no admin) is not code-signed; SmartScreen warns.
- Page editing refuses generated text: numbering, references, citations, bibliography entries, list markers, footnote marks, line-break hyphens.
- Page editing refuses code/macro output: Typst code expressions, `#let` and function bodies, loops, `#set`, imported modules, `#show` replacements; LaTeX user macros; raw/verbatim text; package content ("not editable here — edit in source").
- Structure-changing page edits (e.g. deleting a `\left`/`\right` delimiter, typing a character that opens markup) are refused, not guessed.
- LaTeX character mapping is inferred and checked glyph by glyph; unmapped text is not page-editable; exotic catcodes and text-rewriting packages (`siunitx`, `cleveref` names, TikZ) stay source-only.
- LaTeX navigation is line level (SyncTeX) outside mapped text.
- pdfLaTeX: typed `"` becomes ` `` `/`''`; non-Latin text and combining marks are LaTeX errors. LuaLaTeX: missing glyphs give one warning per font.
- Mixed-direction lines: caret approximate exactly at a direction boundary.
- Typst content included twice is not detected as duplicated and stays editable in both places.
- If concurrent edits (source editor, agent) make page keystrokes unplaceable, typing pauses with a message; nothing is applied at a guessed position.
- Edit-to-page time (debug, Ryzen 7 9800X3D): Typst ~2–15 ms, Markdown ~16–26 ms, pdfLaTeX ~0.3–0.45 s, LuaLaTeX ~0.8–1 s.
- Markdown math is a declared LaTeX-math subset; unsupported commands show a marker and a diagnostic.
- TeX can read any file the account can read (`openin_any=p` does not confine absolute reads), so LaTeX builds require a trusted folder.
- Typst packages are never downloaded; they must already be in the local package directory.
- R interrupt is unsupported on Windows (IRkernel ignores it); Cancel restarts the kernel.
- Exposition never installs runtimes or packages (needs ipykernel + jupyter_client, IRkernel, IJulia).
- R/Julia kernel messages are HMAC-signed but unencrypted over loopback TCP; Python uses CurveZMQ only when pyzmq, jupyter_client and ipykernel support it, else also unencrypted.
- Research sessions need a trusted folder; switching or closing the folder, or revoking trust, detaches them.
- Lean "Checked" certifies the listed declarations as kernel-checked in the audit's own elaboration, not how the text reads (a file can redefine its syntax). A file written to behave differently under the audit is caught only when it drops a declaration the language server indexes; otherwise the list shows what was checked.
- A trusted Lean file's code runs with the user's privileges while compiled; deliberate tampering with the toolchain or other processes is not contained.
- Lean audit programs target Lean 4.35 APIs; toolchains they do not compile on report Not verified; kernel re-checking large dependencies (Mathlib) is slow.
- Lean goals are plain text; third-party infoview widgets are not executed.
- Agents: one provider (Anthropic Messages API); live behaviour is covered only by the opt-in `live-agents`, `live-restricted`, `live-graph`, `live-workflow`, and `live-review-m8-agent` scenarios (spend credit).
- Trusted native code (kernels, approved commands, Python, LaTeX, Lean) runs as the user and can read the stored API key.
- Restricted execution needs Docker with a locally present image providing `/bin/sh` (`sleep` for the in-container time limit); no pull, no native fallback.
- the startup container sweep runs only when an image is configured; a sweep failure is only printed to stderr (the first restricted job retries).
- the liveness pipe covers batch containers only; interactive restricted containers would rely on the time limit alone (the app starts none).
- Processes created through system services (WMI, Task Scheduler, COM) can outlive a job.
- Path resolution and the following file operation are separate steps (TOCTOU against hostile local processes).
- Files with mixed line endings open read-only until normalized.
- Binary, legacy-encoded (not UTF-8 / UTF-16 with BOM) and >10 MiB files are not opened as text.
- Editor links are never opened; they are copied to the clipboard.
- Project graph extraction never expands macros or evaluates code: LaTeX theorem-like environments count only with standard names or a literal `\newtheorem`/`\declaretheorem` earlier in the same file (not one in another file or a package); Typst recognises the default theorem function names and ctheorems (`thmbox`/`thmplain`/`thmproof`) definitions in the same file only, and links no proofs; Markdown only Pandoc fenced divs with the default class names; remarks and examples are not entities. What is not interpreted is reported as partial coverage.
- Lean declarations generated by macros, elaborators, or notation are not recognised, and Lean use-site references are not extracted. The Lean audit reports no declaration dependencies, so formal dependency edges are unavailable and formal evidence is never current against imported modules (freshness unknown, then stale after the file changes).
- Scripts contribute only literal imports of project files; data files a script reads at run time are not recorded (research pins them only when declared as experiment inputs). Notebooks (`.ipynb`), datasets, assets, and configuration files are known only as resources (coverage unsupported).
- *code*: `.ltx` files are not indexed (the LaTeX extractor accepts them, the admission policy does not).
- A reconciliation scan covers at most 32 folder levels, 200,000 folder entries, and 20,000 files; files beyond a bound stay as they were (unknown, not removed). *code*: the bound reached is reported in `graph_reconcile`'s result only, not in the UI.
- A rename or move keeps its identity only when the old and new paths are seen in the same reconciliation pass and match uniquely; otherwise the new path gets a new identity and the old one is tombstoned. *code*: tombstones are never purged.
- Evidence freshness is computed against the last reconciled content of each file; while files are pending, the Graph page says answers may not include the latest edits.
- A folder that cannot hold `.exposition/graph.sqlite3` (read-only) gets a temporary in-memory graph: nothing curated persists, and the Graph page offers no changes or saved layouts.
- Graph canvas: edges are straight lines (parallel ones bowed) and can pass behind other nodes; there is no edge routing; no context menu; one saved layout per section, with no UI to create, rename, or delete views.
- *code*: "Reindex project" (`graph_reconcile`), manual backups and the backup list (`graph_backup`, `graph_backups`), and the operation list (`graph_operations`) have no UI; backups are restored from the unavailable-graph recovery choices.
- Workflow presets exist for Python and Lean only (an R or Julia computational study gets no draft); R and Julia steps are added to a workflow by hand (or by an agent). Restricted R and Julia batches need their own configured local image (no default; the Python image is never used), which must provide `Rscript` / `julia` and every package the code uses; they record no interpreter version or package list, only the image identity.
- At most 3 workflow runs are active at once and one per workflow; within a run at most 4 steps run at the same time (the workflow's `maxParallel`, default 1), under fixed application-wide limits (4 in flight: 2 restricted, 2 native, 2 agent, 1 Lean). There are no retries and no open-ended loops: conditions are fixed predicates, for-each takes at most 20 values, until at most 10 iterations. A run's budgets are derived from its plan and cannot be edited; the time budget is wall-clock time, not reserved per step.
- *code*: a step waiting for a slot or for its budget reservation stays `pending` (there is no "waiting" state) and holds back the later steps of its run; slot waiting counts against the run's time budget, and there is no ordering between runs waiting for the same slot.
- JSON conditions compare numbers exactly as decimals, but a number in the JSON document that has a fraction or lies outside the 64-bit integer range is first read as a double-precision value; a JSON-compare condition can be set on any dataset output, and a dataset that is not JSON fails the step at run time.
- Batch parameter values reach the code as environment variables (`EXPOSITION_PARAM_<NAME>`, one line, ≤ 4096 bytes; `value` ≤ 1000 bytes); a value that looks like a secret is refused only when the batch is about to run (validation accepts it, and it is stored in the saved definition). `EXPOSITION_ITERATION` is set only for repeated steps. Seeds are distinct per instance by hashing, not guaranteed unique.
- A step skipped because a condition did not hold does not fail the run, even when it would have produced a required outcome (the outcome reads Not produced with the reason).
- A native Python step's recorded packages are only the nine that research discovery checks (R: the runtime and IRkernel; Julia: the runtime); a restricted Python image's package list is captured once per image identity by an extra short container run before the first batch in that image (limited to 30 s), and a failed probe is retried by every later batch in that image. Reproduction drift compares the configured model; the served model is recorded beside it.
- Workflow triggers: one per workflow (enabling another replaces it, as the dialog says); a runner briefly unavailable when a trigger checks (for example Docker not running) suspends it until re-approved; revoking trust suspends every trigger of the folder, including those without native steps; triggers listen only while their project is open and indexed and never catch up; triggered runs that are rate limited wait rather than being dropped; the quiet period is shown and checked for interval triggers too, although it only paces their suspension checks; a model change does not suspend a trigger (standing plans do not bind the provider or model).
- Workflow bundle import is not one transaction: a storage failure part-way leaves the children already saved as imported drafts. A single definition imported with composite references keeps them as written.
- An interrupted run is never resumed or repeated; a step that was dispatched when Exposition stopped has an unknown outcome and may have partly run.
- Restricted Python steps need Docker with a locally present image that provides `python3` and every package the code imports (no pull, no network in the container). Only regular files directly in the output folder with one of 11 exported types (PNG, JPEG, GIF, SVG, PDF, CSV, TSV, JSON, TXT, HTML) are kept: at most 32, 64 MiB each, 512 MiB per batch.
- *code*: a batch's output area is on the host disk and is measured about every 0.5 s; the batch is stopped once it holds more than min(output budget, 512 MiB) + 64 MiB.
- Trusted native Python steps and Lean audit steps run with the user's account privileges and are not contained. Each native batch is a new Python process, not a kernel session.
- The Lean audit step allows at most 600 s (the Lean service's maximum for one check); it audits the file's open document, so unsaved changes that differ from the plan's hash fail the step (`workflow.inputChanged`).
- A workflow promotion is always prepared at the end of the manuscript. Prepared reviews are held in memory for 30 minutes; after a restart a pending one reads Expired and the run must be repeated to prepare it again.
- Interactive research sessions run trusted native; restricted research execution exists only as the workflow Python, R, and Julia batch steps.
- *code*: workflow canvas positions are kept in browser storage per workflow, not in the project or the definition.
- An agent review answer is kept up to 65,536 characters; a longer one is cut to that length, ending in "…".
- Project creation declares required tools but never installs them; a project is created only in a new or empty folder.
